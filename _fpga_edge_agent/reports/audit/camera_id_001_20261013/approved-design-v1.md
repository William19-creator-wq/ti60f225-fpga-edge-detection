## B. 整体行为与验收

R1：原 `w_arstn` 释放后，在 `core_clk` 域安全释放诊断复位，再等待至少20ms。每次逻辑复位只探测一轮，顺序固定为 0x30:3107、0x30:3108、0x32:3107、0x32:3108。地址为7位；总线上对应写/读地址字节60/61及64/65。

R2：每次读取按 START → 设备写地址 → 寄存器高/低字节 → repeated START → 设备读地址 → 8位数据 → 主机结束 NACK → STOP。只写寄存器地址指针，不写传感器配置数据。

R3：设备地址 ACK 由回复 `ack_mask[0]` 记录。正确 ID 必须是该地址的两次读取各自完整成功、tag匹配、四个从机 ACK 全部有效、总线已释放，且3107=CD、3108=6B。主机在读末发送 NACK 是正常结束，不能当作从机错误。

R4：普通 NACK 且已安全释放后继续下一笔；超时、仲裁、协议/tag错误、隔离或未释放回复，记录故障并停止本轮。探测开始后按时钟上界设置名义250ms总期限（100MHz实钟下252.5ms），到期禁止新请求，释放本主控的两根线并停在故障终态；仅最后一笔同沿有效终结允许下一拍提交完成，详见E5。外设仍拉低时不能声称总线已恢复。不自动发额外恢复脉冲、不自动重试。

R5：LED 结果粘滞保持至 SW0 逻辑复位或重载；D0 沿用 DDR 心跳。如下灯义仅适用于本版，不能与 CAM-DIAG v1 的灯义混用。

| 灯/引脚 | 本版含义 |
|---|---|
| D0/P13 | 原 DDR 校准心跳，不参与 ID 资格 |
| D1/N13 | 已经过启动等待，开始本轮探测 |
| D2/G3 | 0x30 至少一次设备写地址 ACK |
| D3/N2 | 0x30 的两字节 ID 均有效且为 CD6B |
| D4/G4 | 0x32 至少一次设备写地址 ACK |
| D5/E1 | 0x32 的两字节 ID 均有效且为 CD6B |
| D6/E2 | 四笔探测均取得已释放终态；普通 NACK 也算完成 |
| D7/M2 | 超时/仲裁/隔离/协议等总线故障；普通 NACK 不点亮 |

R6：同一时刻只有新的探测主控驱动 SCL/SDA；开漏只驱动0或释放。保留 `o_cam_rst_p=~w_arstn`，不依据“未应答”擅改电气状态。原视频/DDR结构保留，但不会因本探测执行摄像头配置；画面不是本轮验收标准。

R7：新产物、对应设计和哈希、编译日志、下载记录、用户灯态必须对应。ID探测成功仅证明该次寄存器通信，不代表摄像头图像通过。

正常样例：0x30读得CD/6B，0x32两笔地址NACK，则 D1/D2/D3/D6亮，D4/D5/D7灭。边界样例：两个地址均NACK，D1/D6亮，其余新灯灭；这与“还没有跑完”不同。故障样例：SCL无法释放导致隔离，D7亮、D6灭，已取得的记录可保留，剩余请求不发出。两地址同时读到正确ID时分别记实，不静默选一个地址。

## C–D. 模块、接口与组合检查

整体连接：现有时钟/复位 → IF1 → 探测调度M1 → IF2请求/回复 → 已验证主控M2 → IF3开漏引脚 → J4摄像头；M1结果 → IF4 → 八灯。既有视频链保留，不消费探测结果。

| 模块/计划文件 | 职责及边界 |
|---|---|
| M1 `rtl/cam_id_probe/camera_id_probe.sv`（新建） | 启动等待、四笔调度、资格判定、超时和灯态；不生成位级I2C波形 |
| M2 `rtl/cam_id_probe/i2c_register_master.sv`（原样复用） | 完整寄存器读事务、ACK/数据、STOP/隔离；不选择地址、不管理LED |
| M2依赖 `rtl/cam_id_probe/sc431hai_profile_pkg.sv`（原样复用） | 原主控原因编码/常量；不实例化配置ROM或完整配置层 |
| M3 `rtl/ti60f225_oob_top.v`（局部改动） | 替换原相机I2C实例及输出驱动、连接M1、映射七个LED；D0和相机复位表达式保留 |
| 工程 `ti60f225_oob.xml`（局部改动） | 按pkg→master→probe顺序加入三文件，保留其余依赖与原调试核流程 |

M1外部端口约定（全部为1位）：输入 `clk`、低有效 `arst_n`、`scl_i`、`sda_i`；输出 `scl_drive_low`、`sda_drive_low` 以及 `started`、`address30_ack`、`id30_match`、`address32_ack`、`id32_match`、`all_done`、`bus_fault`。两个 drive_low 输出已在M1内部按复位/故障资格门控；M2原始驱动用独立内部线，不直接出模块。

IF1：使用现有 `core_clk=100MHz` 上升沿，保留10ns时序约束。M1的 `clk/arst_n` 分别接 `core_clk/w_arstn`；M1内两级复位链从 `w_arstn` 异步置复位、同步释放，得到同步高有效 `probe_rst` 供 M1/M2。复位期间M1的 drive_low 输出强制为0，所有资格/计数清零。原相机复位不经过此新增链，不增加其脉冲。

IF2请求：`req_valid/req_ready`、`req_read=1`、`req_device[6:0]`、`req_register[15:0]`、`req_data[7:0]=0`、`req_tag[63:0]`；均无符号。只有上升沿 valid且ready接受，等待时所有字段不变。tag分别1、2、3、4，不回绕。`cancel_valid=0`、`cancel_tag=0`，本轮没有软件取消接口。

IF2回复：`rsp_valid/rsp_ready`、tag64、data8、reason8、outcome2、phase4、ack_mask4、drained1、quarantined1。M1仅WAIT_REPLY接收，只有握手且tag正确才提交；正常数据资格为 outcome=0、reason=NONE、drained=1、ack_mask=1111。NACK且drained可继续但该字节无效；其他失败进入FAULT。ID字节和值的有效位分开保存，未读到不能用零代替。

IF3：`scl_i/sda_i`进入M2现有两级同步器；`scl_drive_low/sda_drive_low`为1表示拉低。M1只有诊断复位已释放且未强制停止时才放行M2对应驱动。顶层OUT固定0，OE直接接M1门控后的drive_low；1使能/0高阻的极性与现有peri一致。现有SCL/SDA的IN、OUT、OE均未启用I/O寄存器、无I/O时钟配置，可连接100MHz域内部同步器；不留5MHz域控制交叉。原 `u2_i2c_master_ctrl_top` 不再实例化，不能保留两套并行驱动。主板原3.3V上拉和原I/O配置保持。

IF4：D1–D7为M1同域稳定记录，直接供人观察，不进入其他时钟域控制。D0仍来自原时钟域。读灯无需把八位当同一帧数据快照。

组合检查：单请求在途、单回复在途，无队列丢失；请求保持至接受、结果保持至消费。字节身份由完整tag及索引一致性约束，顺序固定。原主控输入/输出语义已读源码核对，避免把Wishbone完成当摄像头ACK。使用100MHz及原已验证参数，不引入新5MHz分频假设。每次复位作废所有在途结果；超时先关闭引脚驱动，不继续下一设备。

## E–F. 局部草图与语言契约

M1状态为 WAIT_POWER、PREPARE、ISSUE、WAIT_REPLY、NEXT、DONE、FAULT。局部数据包括启动计数21位、总期限计数25位、事务索引2位、两地址各16位ID与2位有效掩码、两地址ACK记录、开始/完成/故障记录；均无符号。M2保留自身tag和同步器，不修改其内部FSM。

1. 复位清所有记录、计数及有效位，两线释放。复位释放后按 `CLK_MAX_HZ=101000000` 计算20ms，共2,020,000拍；计数饱和不回绕。100MHz实钟下实际等待约20.2ms。
2. 等待结束，置“开始”，索引0进入PREPARE。以索引选择固定地址、寄存器和tag。ISSUE保持请求，握手后才进入WAIT_REPLY；同沿的旧状态决定动作，不在同沿假定下游已有回复。
3. WAIT_REPLY收到匹配回复时，先记录本地址ack_mask[0]；完整成功才存对应ID字节并置其有效位。普通已释放NACK保留该字节无效；故障转FAULT。
4. NEXT在下一拍用已提交的字节和有效位更新该地址“正确ID”记录，防止最后一个字节尚未生效就比较。索引0/1/2依次前进；索引3处理后进入DONE并点D6。两地址独立，不混用旧字节。
5. 从第一笔探测开始计总期限25,250,000拍；终态前饱和。期限到达后禁止再ISSUE，通常立即FAULT；唯一宽限是同沿收到第4笔tag匹配、drained=1且为完整成功或普通NACK的终结回复，允许NEXT再用一拍提交ID资格和DONE。此前已收到第4笔合格终结而正在NEXT的同沿，同样允许完成；其他中间回复不延长期限。FAULT点D7、强制释放本模块驱动、停止新请求；M2 enable置0让其停止，不能将释放驱动误记为外部总线已经回高。DONE/FAULT直到逻辑复位保持。
6. 非匹配tag、未请求的回复或非法调度状态一律FAULT，不授予ID资格。外部复位优先级最高；正常终态不自动循环，因此人为读灯不会跨轮混淆。

M2参数原样采用 `CLK_MAX_HZ=101000000`、`SCL_HZ=100000`、`TIMEOUT_US=10000`。半周期505拍，实际等同步后的高/低再计时；M2的10ms期限按其原实现为“单状态无法推进”期限，M1另有全轮总期限，二者不可混称。读末由主机发送NACK属于成功路径。

RTL A–L契约：位宽/编码见上，无定点缩放或隐式有符号运算；同域posedge及非阻塞时序提交；接受/交付以IF2握手；invalid不推进字节有效性；有反压时请求/回复正文保持；无时钟延展/故障时四笔低于20ms探测预算，启动等待另计，任何停滞受总期限约束；复位隔离在途数据；地址/寄存器为静态配置，运行时不可改变；无RAM/FIFO/同址冲突；身份为tag而非像素坐标；异步引脚只经M2同步，复位按IF1；SV2009/Ti60F225/I3，新增预算不超过1000 LUT、512 FF、0 RAM、0 DSP，以实际映射差值复核。既有资源XLR30369/60800、RAM121/256、DSP4/160作为估计余量依据，不能当成本版已通过。

C++及跨语言算法映射N/A：本轮只有RTL控制及人工外设观察，不生成C++模型。复用证据只支持数字协议，不能替代真实电气边沿、相机复位、EXTCLK或当前板级验证。

时序覆盖限制：SCL/SDA是异步输入，首级同步器用于吸收采样不确定性；保持原SDC不变，不把同步STA通过宣称为异步pad到首级同步器的时序证明。首级到次级仍需满足core_clk域时序；不新增笼统false-path来掩盖内部失败。
