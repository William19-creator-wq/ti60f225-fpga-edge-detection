# HDMI RGB 格式确定性修复

2026-10-17。依据用户直接授权“无需我的批准, 也不用再写草图, 你按照你的見解写代码測試即可”实施。本文件为实施记录，不另设设计审批。原始官方资料、四候选及既有bit保持原状。

## 证据与变更

四个Bayer候选实机均仍有严重偏色（P10按测试顺序归档），未选择任何一个为正确颜色版。复查共用链路时，确认顶层`.video_format(video_format)`实际为未声明、无驱动的隐式1位wire，却连接到编码器2位输入。P00/P10综合日志明确报告undeclared symbol、1→2位不匹配和no driver。此警告在之前基线中已存在，并非四候选新增；现在单独处理。

本地可读的auxiliary_video_information_info_frame.sv把输入video_format直接写入packet_bytes[1]格式位，其参数VIDEO_FORMAT的默认值不能给这个输入端口赋值。源码注释定义00为RGB。原始编码器内部受保护，不能声称已追踪综合后每一位的实际常量选择；旧版RTL不确定性也不能等同于板上持续输出X。

独立副本work/active/track4_v7_hdmi_rgb_001_20261017复制P00的142项已冻结生产输入，仅顶层一处改为`.video_format(2'b00)`。原P00的Bayer相位、单位gain、gamma旁路、红蓝接线、RAW路径、相机寄存器、时钟、DDR和调试核均保持。准备脚本验证源哈希；build-inputs.json保存前后清单。

## 已完成验证

Questa运行真实AVI信息帧模块。旧实例使用与隐式1位悬空端口等效的{0,Z}输入，新实例用00。遍历VIC 0..127，旧实例均复现未知信息帧字段；新实例的header、RGB格式位、VIC字段、保留区域和8位加和校验全部通过。AVI_PASS cases=128，编译/仿真0错误0警告（宏外onerror的提示不影响运行）。日志在tests/runs下保留。

本测试只覆盖可读信息帧模块，不替代保护编码器、显示器解码或摄像头实机验证。后续构建与时序结果写checks.json。若颜色仍异常，继续定位共同数据路径，不宣称此处是唯一根因。

## 构建结果与人工对照

map/interface/pnr/pgm均返回0。检查142项生产输入，只有顶层上述一处连接变化；原有两个video_format警告移除，无新增综合或流程警告。IO接口/布局摘要和18组setup、18组hold约束关系与P00相同。最小setup裕量0.457ns、hold裕量0.029ns，XLR16554、RAM89、DSP0。旧SDC覆盖限制仍在。

测试文件：artifacts/staging/TRACK4-V7-HDMI-RGB-001/v7_hdmi_rgb_001_v1_P00_20261017.bit。用户手动JTAG下载后约30秒，用白纸、红/蓝物体及肤色对照，移动/遮挡确认实时；此版只有颜色格式固定为RGB，其余按P00。若原先是相机数据或其他共享逻辑出错，偏色仍可能保留。当前状态WAITING_HUMAN_PROGRAM，尚未宣称实机修复。构建、测试、登记均未触发板上下载。
