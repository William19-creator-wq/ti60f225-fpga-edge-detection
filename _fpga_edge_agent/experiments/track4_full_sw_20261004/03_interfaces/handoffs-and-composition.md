# 03 系统级交接与组合设计检查

TRACK4-FULL-SW-001；v0.1；2026-10-04。这里规定整体箭头的语义，不包含实现体。最终RTL端口表、确定位宽/逐拍延迟/CDC实现尚需局部设计，因此本文件不单独获得代码生成资格。

## 1. 全部像素和帧接口的共同契约

- 像素按原1920×1080行优先顺序；x=0…1919、y=0…1079，均无符号，最少11bit。多像素组lane0对应最左像素，逐lane有效标志；输入位置与窗口中心的位置不同，适配偏移及补边策略必须说明。
- RAW像素值10bit unsigned；RGB888三个8bit unsigned分量；Y8为8bit unsigned候选。RAW到RGB的缩窄/饱和须有独立数值契约。前序v6舍弃RAW低2位不是本设计默认已批准行为。
- 身份包含reset_epoch、frame_id、config_id；不从时钟周期推断帧归属。ID位宽、回绕及复位冲刷须局部冻结，当前为逻辑独立字段。
- 有ready的域在指定上升沿valid且ready才接受；未接受的有效数据及sideband保持。无ready的相机接入必须预先提供承接能力，不能借下游停顿改变摄像头时序。
- valid=0代表没有像素事务，不代表黑像素。计数/历史按实际接受推进；流水气泡、行间空白和复位由局部契约定义。
- 源帧一旦完成提交即不可写；只读借用有效期由槽引用管理。完整结果必须绑定同源RGB、边缘、标注和配置；任何半帧/错误结果不能成为DISPLAY。

## 2. 接口卡

每一行均规定提供者→使用者、交接内容、接受/所有权/失败语义。最终名称和物理宽度留在04的设计任务中冻结；以下不能用同名端口直接代替适配检查。

| IF | 提供者→使用者及交接内容 | 前置、保证、生命周期和失败 |
|---|---|---|
| IF-01 | MOD-01 CSI→MOD-02：包型、payload/逐字节valid、SOF/EOF/行事件、错误 | 依实际CSI5.15接口适配；受保护IP与包协议先验证。不接受处理器ready；坏包记入当前源帧错误 |
| IF-02 | MOD-02解包→Debayer职责：RAW10像素组/有效lane、坐标、Bayer相位、采集frame/epoch | 正确解包的有效像素才推进行窗口；4RAW/拍参考输入与2RGB/拍候选输出需要明确转换/FIFO/时钟关系。Bayer相位为配置快照、实际相位未确认 |
| IF-03 | MOD-02→MOD-03及基础输入选择：RGB组、坐标、SOF/EOF/EOL、输入错误、同源身份 | 无算法反压；采集预留源槽，基础计算在SOF另预留结果槽及配置。计算未接纳不影响采集，采集错误传播到该帧全部分支 |
| IF-04 | DDR客户端↔MOD-05：读/写请求、字节地址、长度、数据/字节使能、事务身份、响应 | 地址服务以字节为单位并限于已授权区域，v6候选总线128bit；真实控制器地址映射另核。请求/响应有限排队，取消后排空原事务；写响应成功才计完成。burst/4KiB/ID/超时局部设计 |
| IF-05 | MOD-03→MOD-04：完成源描述符（槽、尺寸、格式、stride、frame/epoch、状态） | EOF/计数正确且全部DDR写响应正常才valid提交；提交将写角色变完整只读。最新指针替换只释放旧latest角色的引用；坏帧不提交 |
| IF-06 | 控制输入/配置管理→调度：完整待用配置、冻结/恢复、配置版本 | 先同步消抖，多字段原子快照。已提交旧配置在SOF/领取任务时采样；同沿新事件下一边界生效。在途任务不可改；非法组合明确拒绝/报状态 |
| IF-07 | MOD-04↔处理链：输入来源、只读源引用/流帧授权、预留结果槽、配置、任务身份、完成/失败归还 | 必须先有输出资源再领取源；帧级源须完整，直播授权须SOF接纳。每个任务独占共享前端；失败取消先排空请求再释放，不能早归还写槽 |
| IF-08 | MOD-06→MOD-07/08：Y8像素/3×3窗口、窗口中心、逐lanevalid、边界、frame/config/epoch | 中值在灰度后；旁路保持身份与所需延迟。Sobel符号扩展、绝对值和阈值单位待局部冻结；单次只选择相应边缘路径，无效不是零 |
| IF-09 | MOD-08前级→精确连接：双阈值分类图、强种子、尺寸/身份、完成事件 | 分类图全部写完成后可读取；所有强边作种子，对可达弱边仅入队一次，邻居不跨行/边界。最大N队列预算；队列空且写回排空后才完成。单跳或固定轮次不满足契约 |
| IF-10 | 完整边缘/梯度→MOD-09：同源边缘图/梯度描述符、配置及输出容量 | 识别只能读已完成同任务图；粗候选后原分辨率核验。结果包含类别/原坐标bbox/圆参数或旋转矩形顶点/分数/身份；列表容量及数值精度后续冻结。空列表与溢出/失败不同 |
| IF-11 | MOD-10→MOD-04待发布：不可变bundle（源RGB引用、边缘及可选图、标注、模式、frame/config/epoch） | 每个必需模块已完成，全部写响应成功且身份相同才可提交；pending深度1，不覆盖。提交后各图只读；错误任务不提交 |
| IF-12 | MOD-04/MOD-10↔MOD-11：完整bundle领取/旧bundle归还 | VSYNC原子切换一个描述符，不分字段跨域采样；无新结果则重复旧帧。旧结果进入RETIRING并仍占3槽池，读取/预取排空确认后才归还引用；欠载报状态并保持HDMI时序 |
| IF-13 | MOD-01→所有模块：域时钟、复位、PLL/CSI/DDR就绪 | 域间各自安全释放；跨域通过握手/FIFO。epoch冲刷未完成或DDR未就绪时不授予新任务；不假定DDR全清零 |
| IF-14 | 所有模块→MOD-12/04/11：任务状态、错误、计数与状态快照 | 采集错误/调度跳帧/显示重复/无目标/溢出分别编码；计数快照一致性及回绕后续冻结。错误可追踪到任务/帧/配置，不自动改正式H/A/R状态 |

## 4. 正常、边界与失败端到端走查

**N-01基础直播**：合法SOF→空源/结果槽与配置快照→IF-03同源分叉→IF-04源RGB和边缘写→IF-05源提交→IF-11等待所有完成并提交→IF-12 VSYNC换帧。源/边缘身份相同才输出；处理分支不能反压相机。

**N-02慢处理**：IF-07预留结果后借用latest→IF-08完整前级→IF-09精确闭包→可选IF-10→IF-11→IF-12。新采集替换旧latest时只释放该角色，不影响正在处理的源。显示可重复旧帧，调度跳帧明确。

**B-01六角色同时出现**：3个结果槽（可含display/pending/working/retiring中的至多3种占用）各关联一个源，再加冻结/latest/capture，最多6份不同源。处理源必须绑定其working槽，不能另有隐藏读者。SOF和complete/pointer更新需证明回收可用，无法接纳的新采集报容量错误，不能覆盖引用源。

**B-02结果拥塞**：display和pending持有两个结果槽，working完成但无法提交；working保持完整，前端不能再领取新任务。下一VSYNC把pending换为display、旧display换为retiring；只有旧读/预取排空确认后retiring槽才回收。任何转移都不使总占用超过3槽。MOD-05仍服务采集与显示，任务不锁DDR等待。

**B-03冻结换配置**：当前显示源被增加freeze引用；新config读取同一RGB生成结果；未完成期间旧bundle继续显示；新完整bundle换入后frame不变config变。恢复只释放freeze角色，其余引用继续有效。

**F-01采集坏行/溢出**：IF-01/03错误→当前源和分支结果失效→排空旧写→下一SOF重同步；IF-05/11不得发布。旧显示继续可用，记capture_error而非scheduler_skip。

**F-02校准/DDR错误**：DDR仍能响应的普通取消按停发→排空→作废归还。IF-13校准失效或控制器不可用则停相关访问→独立于DDR的安全图案；无法排空的槽隔离保留，控制器/客户端安全复位确认后恢复。模型或校准不足的验收保持阻塞，不能强制done。

**F-03无目标/超容量**：IF-10合法空列表可以发布；候选/工作/输出容量超限则携带错误，失败不作合法空列表。保留原测试和失败信息。

**F-04复位/旧响应**：新epoch使旧图/描述符不可发布；所有域冲刷确认前不接纳任务，旧响应按旧事务排空，不能匹配新任务。显示安全图案并保持标准扫描。

## 5. 本层结论

系统层接口与资源归还可以组合成完整路径；关键冲突和适配职责已有定位。这是设计走查结论，不是接口测试通过。04阶段必须补齐实际端口、完整逐拍/数值/RAM/CDC等契约，消除05中的阻塞后才能达到对应范围的READY_FOR_REVIEW。
