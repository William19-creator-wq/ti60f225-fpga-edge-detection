## B. 整体外部行为

| REQ | 行为规则与来源 |
|---|---|
| FM-01 | T4-B1/DER-02：采集不能被算法ready反压；合法源只有在最终像素判定和写入完成后才成为可读完整源 |
| FM-02 | T4-A3：latest指向最新成功采集的完整源；冻结引用和处理/显示引用独立，替换latest不释放其他读者 |
| FM-03 | T4-A2/DER-03：每任务锁定完整配置及三ID；同沿配置更新不改变该沿接纳任务的旧快照 |
| FM-04 | T4-B4/A5：原RGB、边缘、标注、模式与身份作为一个完整bundle发布，VSYNC整体换入；旧读排空才归还 |
| FM-05 | T4-A3：冻结选择显示域真实正在使用的源；参数变化在同一冻结源上生成新结果，恢复重新使用直播或latest |
| FM-06 | DER-04/06：结果槽先于源借用，pending至多1，有限资源不被隐含第四个结果或隐藏读者绕过 |
| FM-07 | DER-06/07：失败/取消/旧策略不发布；超时和复位epoch不等于物理DDR事务排空；故障隔离后安全恢复 |
| FM-08 | DER-01/07：槽复用带generation；重复/迟到/非法ACK不释放当前对象；采集失败、算法跳帧、显示重复、无目标分别报告 |

上电后所有槽无有效图像，任务关闭；只有平台、相机输入与DDR按相应契约就绪才接纳。显示可先输出独立安全/等待图案。停止一个任务先停止新增访问，再排空并回收；整机复位需跨域和DDR共同安全确认。

冻结提议的可观察生效点是显示域看到请求后的VSYNC：选择该边沿之前的真实active源，同沿新offer不应用。按键边沿到该VSYNC有跨域延迟，不能把它描述为零延迟冻结。显示返回NO_ACTIVE时，core若已有完整latest则先锁定它；否则进入FREEZE_WAIT_FIRST，在第一份成功源完成提交的原子更新中同时建立FREEZE引用，再从此源生成首个可显示bundle。界面状态要区分“等待首帧”与“已锁定源、等待显示”。此启动策略为待整体验证的新提议，不能虚构它来自正在显示的画面。

普通参数连续变化合并为下一任务的最新快照，不反复取消已接纳任务；冻结、恢复和算法/输入路径切换构成策略屏障，屏障后旧策略结果不再发布。屏障的精确跨域完成点仍受FM-B03约束。

样例：显示A时冻结，显示快照确认A后改变阈值，下一完整结果仍frame=A而config改变；等待中继续显示旧A。边界样例：显示已从A切到B而core的APPLIED尚未到达，冻结必须选B。失败样例：前端OK但源写响应报错，结果不可发布，旧合法显示继续保留。

## C. 模块职责与整体连接

文字连接：相机/采集MOD-03经IF-05向MOD-04提交带源句柄的终态；MOD-04经IF-07预留结果并启动处理；各算法和MOD-05将终态/fence交给MOD-10；MOD-10经IF-11申请发布；MOD-04经IF-12向显示MOD-11提供完整bundle，显示返回应用/退役/冻结快照事件。所有错误经IF-14汇入状态，并反馈停止新接纳。MOD-01的IF-13负责安全复位就绪。

| 局部单元 | 拥有的状态与职责 | 不承担事项/理由 |
|---|---|---|
| FM-LEDGER（MOD-04） | 唯一修改源/结果账本、generation、latest/freeze、任务与策略状态；统一处理原子事件 | 不根据像素内容自行判断源成功，不代替DDR排空证明 |
| FM-JOIN（MOD-10） | 汇合源有效、所选算法终态、数量及输出fence，给带身份的成功/失败候选 | 不自行清引用、换显示或占用新槽，避免多个状态拥有者 |
| FM-DISPLAY-LINK（MOD-04/11边界） | 传递不可变offer、应用和排空ACK、冻结快照/提交/恢复屏障 | 不实现HDMI扫描和具体预取；实际active属于显示域 |
| 相邻MOD-03/05/11 | 分别拥有采集数据、DDR请求、显示读/像素流水及其排空证据 | 只能用完整句柄归还租约，不能直接把槽改FREE |

本批拟自写账本和交接，复用FRONTEND已设计的三ID/任务接口；不复用旧bank_switch充当新所有权管理。输出预留后借源避免无输出空间时占住输入；等待VSYNC不持有DDR仲裁锁。结果绑定覆盖其处理、待发布、显示、预取和退役期间的全部源借用。

整体检查点：02/03已经呈现整体图；本稿反馈六源容量证明前提、真实显示冻结和响应完成三项修订。尚未更改02/03冻结内容，阅读时以本稿的显式缺口说明理解旧层概括；整机下一版本必须正式吸收这些修改。

## D. 接口与组合检查

### D1. 候选类型与有效期

以下字段均unsigned；没有标为冻结端口表。合法范围外一律协议错误，不截断后使用。

| 类型/字段 | 候选位宽与单位 | 拥有者/生命周期 |
|---|---|---|
| source_slot / result_slot | 3位，0…5 / 2位，0…2 | 物理槽编号；未授权/无valid时不可解引用 |
| source_generation / result_generation | 各64位，无量纲 | 每次重新授权该槽时变化，完整句柄随全部完成/归还消息；耗尽策略见FM-B08 |
| epoch / frame_id / config_id | 各32位，与FRONTEND一致 | 外部帧/任务身份，按相等匹配；不以无符号大小推断先后 |
| capture_sequence / job_sequence / policy_generation | 各64位 | 内部顺序和策略身份；不能替代外部三ID防碰撞要求 |
| offer_sequence / control_sequence | 各64位 | 每个未结跨域事务的身份；ACK必须匹配，不因槽相同而接受 |
| source_retention | 5位：LATEST/FREEZE/BIND_R0/BIND_R1/BIND_R2 | MOD-04唯一写者；一个源可以同时拥有多个角色 |
| source_state | 候选3位枚举FREE/CAPTURING/WRITE_DRAIN/COMPLETE/QUARANTINED | 精确编码后续冻结；WRITE_DRAIN仍属于写者 |
| result_state | 候选3位枚举FREE/WORKING/PENDING/DISPLAY/RETIRING/QUARANTINED | 完整但未能发布仍为WORKING并带complete标志 |
| cfg_snapshot / bundle | 三ID、源/结果句柄、各图位置/长度、模式、标注及配置 | 本批语义已分组，完整位布局取决于Canny/识别/DDR图布局，FM-B03/08尚未解决 |
| fence | 句柄、范围/客户端、成功或错误、已接受请求全部排空的证明 | 不是仅有done脉冲；tag宽度、outstanding上限及计数宽度由MOD-05提供 |

只要还有任何写者、保留位、在途请求/缓存/跨域租约或隔离故障，源就不可重用。结果从预留到最终回收始终绑定同一源句柄；源BIND位在这个完整期间保持。合法直播结果可绑定CAPTURING源，但它只读取同源直播分支；DDR源读取和显示必须等待COMPLETE。

### D2. 交接事件

| 接口细化 | 提供方→使用方、接受条件 | 完成保证/流控/复位 |
|---|---|---|
| FM-IF01 源申请/终态 | MOD-03↔LEDGER；接纳合法SOF必须已有空源及输入就绪 | 相机不可反压，如何提前授槽/缓存SOF尚待FM-B01/07；EOF只转WRITE_DRAIN |
| FM-IF02 任务接纳 | LEDGER→处理适配；结果已预留、源/直播资格成立、前端job ready | 与FRONTEND FJ-01相容，首像素必须在job接受后；所有配置/三ID保持到接纳 |
| FM-IF03 内存fence | MOD-05→LEDGER/JOIN；句柄、代次和客户端匹配 | 全部已接受读写事务及缓存清理完成；普通取消不撤销已经握手的DDR事务 |
| FM-IF04 完成汇合 | 算法/采集/内存→JOIN→LEDGER | 成功是所有必需证据的合取；空识别列表可成功，溢出/失败不可成功；pending满保留WORKING |
| FM-IF05 offer/apply/retire | LEDGER↔显示；PENDING完整后提供一个原子描述符 | 收到offer≠应用；只在VSYNC且预取足够时应用。APPLIED回传新旧句柄；RETIRE_DRAINED单独归还旧租约 |
| FM-IF06 冻结快照/策略 | LEDGER↔显示；一次仅一个未结控制事务 | FREEZE_SNAPSHOT→带hold快照→core建立FREEZE→FREEZE_COMMIT。恢复也须结清已发消息；消息与offer的因果顺序待定 |
| FM-IF07 控制/状态 | 已同步的按键/控制适配↔LEDGER | 参数快照原子提交；按键消抖不在本批。冻结/恢复串行化，不让两个脉冲各改半套状态 |
| FM-IF08 安全冲刷 | 平台/全部客户端↔LEDGER | 所有域及DDR安全证明之前无新分配，旧epoch仅用于阻止发布，不能替代地址隔离 |

同域候选控制通道采用valid/ready：valid且ready上升沿为接受，停顿保持全部payload；跨域不得逐位同步bundle，需原子邮箱或异步FIFO。具体通道数、容量、同步级数、复位释放与取消协议尚待物理CDC局部设计，不能把此语义表当最终端口。

### D3. 组合结论

- FRONTEND只保证一个任务输出/状态与计数；它不检查源写成功、显示预取和DDR完成。MOD-10必须补齐这些前提。
- 实际显示active与core DISPLAY影子不同：APPLIED返回前两槽均有BIND，安全引用可保守保持，但冻结来源必须查询显示域。
- RETIRING不限定为一槽。D+R+P换页后可为D+R+R，总占用仍三槽；没有FREE时不授新任务。
- 所有跨域offer、快照hold和预取都归属现有结果槽BIND，不能额外产生第四个无账本源读者。
- 源成功和完整結果发布均以fence为前提。参考bank_sw的W尾拍事件不满足FM-IF03。
- 当前六源占用上界不能自动证明下一SOF有空槽；详见E4反例。平均像素率/DDR带宽也不能证明突发积压或尾响应期限。

## E. 局部详细设计与中文操作草图

### E1. 数据、不变量与状态

源表保存写者状态、源身份/代次、采集顺序、最终错误和5位保留；结果表保存结果代次、绑定源、任务/策略、配置快照、完成位和显示租约。初始无有效图像、引用全无；仅安全复位完成后可将槽授权为FREE。DDR图像内容不要求清零，以有效性隔离旧字节。

| INV | 不变量及理由 |
|---|---|
| FM-INV01 | FREE源无写者、保留位和未结租约；否则新写会覆盖仍使用的帧 |
| FM-INV02 | 一个物理结果槽只有一个代次、一个源绑定，回收前BIND持续有效 |
| FM-INV03 | DDR读取只针对COMPLETE源；直播计算不能绕过显示发布的源完整性检查 |
| FM-INV04 | 发布满足源/所有算法/所有输出fence/策略资格，不能把前端OK当整机OK |
| FM-INV05 | pending≤1、结果总占用≤3，包括退役、跨域在途和隔离槽 |
| FM-INV06 | HAS_ACTIVE由显示域确认具体源，先加FREEZE再解除结果snapshot-hold；NO_ACTIVE由显示域确认并保持策略屏障，core按完整源规则建立FREEZE后结清控制握手 |
| FM-INV07 | 同沿更新只提交一次新账本，增减引用不会互相覆盖 |
| FM-INV08 | 超时、epoch变化和逻辑cancel都不制造物理排空证明 |
| FM-INV09 | 每job配置和三ID不变；外部身份尚存活时禁止静默复用 |
| FM-INV10 | 原因计数分类保留，采集容量失败不冒充算法调度跳帧 |

### E2. 八项操作草图

**FM-OP-01 采集与直播接纳。** 在合法SOF分配边沿检查旧状态中的可用源及就绪条件，为源建立新代次/采集身份和独占写者。采集不依赖结果空槽。若同时有前端容量、结果空槽和足够直播FIFO，则在同一原子决策中预留结果、绑定该源并锁定配置；否则只采集并记录算法跳帧。没有源槽属于采集容量失败，不允许覆盖引用源。FRONTEND的job接受与首像素分沿，适配必须缓存首组像素。计算支路停顿/失败不能反压RGB采集。SOF不可暂停与提前授槽的物理实现仍待FM-B07。

**FM-OP-02 源提交与latest。** EOF把源转为WRITE_DRAIN，保留写者；等待最终行/包/像素判定、请求及数据FIFO清空、全部B响应成功和该源不存在可迟到写入。全部满足才COMPLETE。坏源使关联直播结果失败，不进入latest。若允许多帧同时排空，按capture_sequence选择最新成功帧，晚完成的旧帧不得替换较新latest。替换只清旧源LATEST位，其FREEZE/BIND仍保留。不能为了下一SOF提前丢弃唯一latest来掩盖容量不足。

源回收是账本统一提交的最后一步：先合并本沿全部保留位新增/撤销与租约归还，再检查无写者、无保留位、无未结事务且无隔离条件的源，提交为FREE。它覆盖旧latest失去最后引用、结果退役/取消释放最后BIND，以及旧帧迟完成但未取得LATEST的情况。坏源也只有排空且关联任务释放引用后才可回收。不能在中间步骤看到旧引用归零就回收，漏掉同沿新增FREEZE/BIND；新分配只能从下一沿使用该FREE源。

**FM-OP-03 帧级任务领取。** 处理器空闲且前任务适配已排空时，先找到结果FREE，再在同一决策中选择已完整的FREEZE或旧状态latest并设BIND；没有源则不留下半个任务。锁定源/结果代次、三ID、配置和policy_generation。所有DDR返回按本任务句柄核验。FRONTEND OK只交给完成汇合；FS-01消费后仍遵守其下一job接纳空隙，不强迫同沿重启。

**FM-OP-04 完成汇合与pending。** 收集源有效、前端OK、所选后续算法终态、识别终态及各输出fence；逐项比对句柄、三ID、数量、配置和策略。合法空列表是成功，溢出不是空列表。全部满足标记WORKING完整；pending满则保持槽和BIND，不覆盖pending、不占DDR锁等待显示。pending空且有发布资格才形成不可变bundle并分配offer_sequence。APPLIED或CANCELLED_DRAINED等终态尚未确认时，该槽不得重用。

**FM-OP-05 显示换页与退役。** 显示原子接收offer后进行候选预取，收到描述符不等于可显示。只有VSYNC到达且预取条件满足时才整体切active，旧active加入退役集合，按有序事件通道回传APPLIED新旧句柄。core此时才更新DISPLAY影子。显示停止为旧对象发新读，等待请求/返回队列/缓存/像素流水都不再引用它，再发RETIRE_DRAINED；core核验代次后回收旧结果及BIND。旧读很慢可占两个RETIRING槽，不能强制提前回收。

**FM-OP-06 冻结真实画面。** core接纳冻结后进入FREEZE_PENDING，禁止尚未提出的新旧策略offer；已提出或同沿握手的offer仍按实际事件登记，后续明确撤销。向显示发送带control_sequence的FREEZE_SNAPSHOT。显示在请求可见后的VSYNC先于新offer选择边沿前active，建立snapshot-hold并返回源/结果句柄和实际应用序号。core收到合法快照先增加源FREEZE，再回FREEZE_COMMIT，显示收到后才解除移交hold。旧pending需撤销；若已预取，停新读并排空后才返回CANCELLED_DRAINED。如果offer已在更早VSYNC应用，快照就指向它，不可把它当未应用pending释放。

没有active时显示返回带control_sequence的NO_ACTIVE并保持“禁止应用候选”的控制屏障，此时没有源snapshot-hold。core收到后按B节选旧完整latest；若没有而本沿恰有成功完成源，则将这份完成源与FREEZE位原子提交；否则进入FREEZE_WAIT_FIRST，首份成功源COMPLETE与FREEZE原子提交，不留被回收的空隙。这是引用保留事件，不让job在同沿提前读取新完成源。随后FREEZE_COMMIT携带所选源句柄，显示确认控制屏障移交；只有符合冻结源/策略的新bundle才可应用。等待期间恢复仍须结清这个未结控制事务，不能把NO_ACTIVE当全流程结束。具体消息编码/渠道在FM-B03闭合。冻结建立后重处理沿用源frame而更新config；数据保留依靠真实账本，不能只显示一个“冻结”标志。

**FM-OP-07 配置、恢复与模式。** 参数事件提交完整新快照；与job同沿时job仍用旧快照。连续参数更新合并到下一job，不改变在途任务。冻结/恢复/算法及输入路径切换产生策略屏障，旧策略任务可取消但必须排空，旧结果不能越过屏障迟到发布。快速冻结后恢复时顺序结清已发快照/移交，再解除冻结；不能抹去未ACK消息。恢复只撤FREEZE位，其他BIND继续保护源；前端换路必须排空，直播等待后续SOF，慢模式领取届时latest。显示恢复屏障与策略资格的最终事件顺序仍在FM-B03中，当前不宣称已逐拍闭合。

**FM-OP-08 取消、错误与复位。** 取消首先禁止新增请求，要求前端终结，已经交付的输出前缀整job无效。取消同沿真实发生的像素/DDR握手仍计入在途账本；等前端终态、所有读写fence及跨域租约都归还后才能释放WORKING/BIND。可排空错误作废相关对象，保留旧合法显示。DDR失效、无法排空或句柄冲突则QUARANTINED；超时只报错，不清成FREE。epoch改变能阻止发布却不能阻止旧写落入重用地址，必须等待控制器和客户端安全冲刷。DDR不可用时显示独立图案，不能据此判显示功能验收通过。

### E3. 同沿旧状态与提交顺序

各决定基于边沿前状态，计算一次下一状态并原子提交位图；不使用多个独立分支对同一引用作覆盖式读改写。控制事件不能撤销该沿已经由valid&ready形成的真实接受。已经提出且未接受的valid/payload也遵守保持契约，不能因模式命令无声撤回。

| 同沿事件 | 候选确定规则 |
|---|---|
| fatal/reset与其他事件 | 禁止新申请及发布，保留隔离/排空占用；实际已握手事务仍需账本记录 |
| cancel/源错误与末次成功输出 | 记录真实传输，失败优先，禁止发布 |
| EOF与末写响应 | 可以形成源完成候选，但必须另外满足终态和全部fence |
| 新源完成与job领取 | job读旧latest，新源下一边沿才可领取 |
| 配置提交与job领取 | job用旧完整快照 |
| 槽回收与新申请 | 本提议不作同沿回收再分配；下一边沿可用，有利于读回和时序，需计入SOF预算 |
| 生命周期命令与新任务 | 禁止尚未提出的新申请；已同沿握手的旧策略job必须登记并保留引用、取消其发布资格。FRONTEND在IDLE不处理cancel，因此要在后续ACTIVE沿提交取消并等待终态/排空，不能只在接纳沿脉冲cancel；普通参数更新仍用旧快照规则 |
| freeze与resume物理事件 | 控制适配先串行化；同时输入提议resume优先并记录合并，精确编码待FM-B08 |
| 显示VSYNC、freeze和候选 | freeze先选旧active，候选后续明确撤销/排空 |
| APPLIED与旧退役归还 | 同一有序事件流先建立退役关系再归还；若可同拍双事件必须另有明确编码，不默许乱序 |

### E4. 六源槽的证明边界与反例

三个物理结果槽绑定的不同源集合B最多3；冻结F最多1；latest L最多1；持有写租约的采集集合C必须包含EOF后的WRITE_DRAIN。在健康运行且C最多1时，B∪F∪L∪C最多6。这是占用上界，**不是下一SOF总有空槽的证明**。

反例：R0/R1/R2分别绑定S0/S1/S2，冻结S3，latest S4，S5已EOF但写响应未收齐。六槽全占；下一SOF到达，覆盖任何槽都会破坏写者/读者/冻结或唯一latest。不能把这个采集能力失败改名为普通调度跳帧。

可选闭合路线：①保留六槽，证明上一帧写租约和跨域确认在下一SOF分配之前完成，本稿无同沿释放复用所以至少提前一个分配边沿；②增加源槽，并给出最大同时写租约数K，保守需求为3+1+1+K，K包含即将接纳的新写者，因此SOF前未结束旧写租约不得超过K−1；③明确修订源保留或采集要求再证明。有限槽无法吸收无限DDR停顿。当前先保留整体六槽假设并标条件未满足，不能任选方案写成已证。每增一RGB源槽至少增加6,220,800字节，地址对齐和其余资源另算。
