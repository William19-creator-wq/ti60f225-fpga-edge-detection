## 1. 控制代码中是否存在会导致"始终首地址 NACK"的错误

**结论：没有找到这样的代码错误。**

- **i2c_register_master.sv**【源码事实】
  - START：SCL、SDA 均为高并保持半周期后，拉低 SDA，再保持半周期。
  - 发送：SCL 低时改变 SDA，第 9 个时钟释放 SDA，在高电平结束前采样 ACK。
  - 地址：`{req_device,1'b0}` 中 0x30 → 0x60、0x32 → 0x64，正确。
  - 速率：HALF 按 101 MHz 计算，实际 core_clk 为 100 MHz，SCL 约 99 kHz。
  - 时间：SDA 数据建立时间约 5 µs，保持时间约 3 个时钟。
  - 未发现极性或时序错误。
- **顶层与 peri**【源码事实】
  - `io_cam_s?a_OUT=0`，`OE=drive_low`；peri 为 inout，IN/OUT/OE 均无寄存器，OE 高有效，与官方 v7 一致。
  - 引脚为 B14/GPIOR_18（SDA）、D12/GPIOR_20（SCL）、C12/GPIOR_16（RST），与原理图 J4 第 2、3、6 脚一致（已对照 v4_schematic_j4.png）。
- **复位与等待**【源码事实】
  - 复位释放后等待约 20.2 ms，满足手册 T4 ≥ 4 ms。
  - RST 低、RST 高两种情况都测过。
- **诊断盲点**【源码事实，同意 Codex 的判断】
  - TX 只检查"发 1 读到 0"，不检查"发 0 读到 0"；START_HOLD 也不回读 SDA 低。
  - 因此"SDA 输入卡在高"或"SDA 输出没有真正拉低"都会表现为普通 NACK，D7 不亮。
- **另一条独立证据**【推断】
  - 官方 v7 自带的 I²C 控制器（另一套实现）同样没有使相机工作。
  - 两套独立代码都失败，问题更可能在物理链路，而不是某一份代码。

**尚未排除**：

- 模组 RST 的内部极性和传递；

- 传感器本体是否损坏。

**一条值得复测的线索**【实测事实 + 推断】

17:55 的万用表读数：

| 电阻 | 一端 | 另一端 | 推算电流 |
|---|---|---|---|
| R221（SCL） | 3.357 V | 3.114 V | 约 52 µA，SCL 线上有负载 |
| R222（SDA） | 3.354 V | 3.356 V | ≈ 0，SDA 线上几乎无负载 |

- 若测量时总线空闲：SCL 上有约 25 kΩ 量级的负载（例如模组侧接到 1.8 V 的上拉或电平转换器），SDA 上却没有。这种不对称与"SDA 没有接到模组"相符。

- 限制：17:55 运行的是更早的配置诊断程序，当时总线是否空闲没有记录。所以这只是线索，需要在已知空闲状态下复测（见第 4 节）。

## 3. V6/V7 的复位与 LED 差异，以及黑屏/花屏的来源

**官方各版本引脚**【源码事实，见 0927 资料包 10_Ti60f225_sc431hai2hdmi_demo】

| 版本 | i_arstn | led[0] | led[1] | pll_inst4 复位/锁定脚 |
|---|---|---|---|---|
| v1 | GPIOL_07 (KEY0) | GPIOR_21 | GPIOR_22 | 无 |
| v6 | **GPIOR_27 (P13 = D0 灯)** | GPIOR_21 | GPIOR_22 | 无 |
| v7 | GPIOL_07 (KEY0) | GPIOR_27 (D0) | GPIOR_24 (D1) | 无 |
| 031 / REFINE B01 | GPIOR_27（与 v6 相同） | GPIOR_21 | GPIOR_22 | **有，且锁定信号并入 w_arstn** |

- 031 的引脚沿用了 v6 的错误映射，v7 已改正。
- 实测依据：v7 中 led[0]=GPIOR_27，用户看到 D0 闪烁，证明 P13 是 D0 灯。
- 推断：v6 和 031 的复位输入接在 LED 三极管基极上，电平不稳定，会造成黑屏或"先识别后无信号"。

**花屏 vs 黑屏**【推断，与 Codex 一致】
- v7 的帧缓冲在没有任何有效相机帧时也照常读 DDR 并显示，拔掉相机仍花屏，所以花屏不是相机像素。
- 031/REFINE 必须等第一帧处理完才发布，因此相机不出帧时应是"有同步的黑屏"。
- REFINE B02（复位已改到 KEY1/P14）仍然 D0 不亮、无分辨率，说明还有一个独立的启动问题，见第 6 节。

## 4. 最少步骤、最有区分力的下一项检查

全程只用普通万用表；只测已经测过的 R221/R222 两端，不碰 J1/J4 焊脚，不外加任何电压。

1. 下载 RST-COMPARE v1（已有 bit，SHA256 5F672543…198C），等 D6 亮。此时探测已结束，两线都已释放，总线确定空闲。测 R221、R222 两端电压，记为 A 组。
2. 断电，拔下摄像头排线（只拔模组端或主板端均可），上电，重新下载同一 bit，等 D6 亮，再测 R221、R222 两端，记为 B 组。
3. 判读：

| 结果 | 含义 |
|---|---|
| A 组 SCL 有约 0.2 V 压降，B 组消失；SDA 两组都约 0 | SCL 能到达模组且有负载，SDA 没有。优先怀疑 SDA 这一路（J4 第 2 脚、排线、模组 J1 对应脚） |
| A 组 SCL、SDA 都有压降，B 组都消失 | 两线都到达模组，转向 RST、时钟、模组本体 |
| A、B 两组都无压降 | 模组对两线都不加负载（可能本来就设计如此），本测试无法区分，改用第 5 步 |

4. 预计总共两次下载、八个电压读数，不需要新编译。
5. 第 3 步无法区分时，再整合 Codex 已批准的慢速电平检查：在 BOTH_LOW 阶段测 R222 两端，若约 3.3 V 压降，说明主板 SDA 能拉低。如能找到模组侧 I²C 上拉，再测其两端，可判断 SDA 是否到达模组。

## 5. 慢速电平模块 camera_bus_level_check.sv（进行中，未整合、未验证）

【源码事实】
- 四个阶段依次为：两线释放 → 仅 SCL 低 → 两线低 → SCL 低、SDA 释放；最后先放 SDA，至少 1 ms 后再放 SCL。
- SDA 只在 SCL 低时变化，不会形成 START/STOP，因此不会发出任何事务，满足"不主动发配置事务"。
- 各阶段回读实际电平，出错先放 SDA。复位撤销时异步撤销驱动。32 位计数器不会回绕。
- 能检出"主板 SDA 无法拉低"或"输入卡死"；**不能**证明 SDA 到达模组。
- 小建议（不改行为，可直接写进测量步骤）：把"IDLE 阶段、接相机 vs 不接相机"的 R221/R222 对比加入测量步骤，用来判断负载在哪一侧。

## 6. 对 TRACK4-031-REFINE-001（Claude 负责的整机副本）的意见

- B02 已把复位改到 KEY1，但 D0 仍不亮、HDMI 仍无同步。
- 与可用的 v7 对比，剩下的差异只有 031 自加的时钟结构：
  - pll_inst4 的锁定信号并入 w_arstn；
  - pll_inst4 输出 100 MHz 给 DDR 核心；
  - MIPI_TX_PLL 改用独立反馈，core_clk 改为 90.9 MHz。
- 建议的 v0.3 修订（需用户批准）：
  - (a) 时钟结构恢复为 v7 的实测可用形式：pll_inst4 去掉复位/锁定脚，不并入 w_arstn；core_clk 恢复 100 MHz 并以自身作反馈；DDR 核心时钟用 core_clk；SDC 相应调整。
  - (b) D2–D7 显示 KEY1 电平、各 PLL 锁定和 w_arstn。
  - (c) 第一帧到来前显示测试图（原 B-7），使 HDMI 链路可以脱离相机单独验收。
- 这份修订不使用相机，可以与相机诊断并行编译。但下载需要占用同一块板，应和 Codex 的诊断错开进行。
- 相机 ACK 恢复之前，整机不可能出现真实画面。
