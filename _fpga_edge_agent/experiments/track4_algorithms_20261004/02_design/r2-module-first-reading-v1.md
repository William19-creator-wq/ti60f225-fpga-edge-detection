# R2 流段 v1：从中文草图进入模块代码的阅读入口

2026-10-05。本文只是现有设计的短阅读入口，不新增行为、接口、文件范围或审批。权威设计是 [TRACK4-ALGORITHM-R2-STREAM-IMPLEMENTATION-001 v1](../../../planning/design-TRACK4-ALGORITHM-R2-STREAM-IMPLEMENTATION-001.md)，状态 READY_FOR_REVIEW / NOT_APPROVED / NOT_IMPLEMENTED / NOT_RUN。

## 先看整体

复用已交付的 R1 灰度/可选中值 → 5×5 高斯 → 高斯结果的新 3×3 窗口及 Sobel → 整数方向 → 分支交接 → NMS 窗口 → 非极大值抑制/双阈值分类。控制器负责启动、停止、错误与完成结算；独立图样/CRC/LED 外壳用于软件和四引脚 FPGA 工程验证。

本批先把这一段实际写出并验证。完整 Canny 的滞后连接、识别、相机、DDR 和 HDMI 属于后续整合目标，不是本批纯算法编码前必须全部解决的条件。

## 再看每个模块怎样写

| 模块 | 中文代码组织草图 | 对应现有设计 |
|---|---|---|
| 高斯 gaussian5x5_pair | 行 RAM 与读回有效状态分开；组合逻辑先扩位算加权和，时序逻辑依旧值推进五级流水；系数 1/4/6/4/1，只在最终总和加 128 后右移 8 位；补下边/右边由明确 phase 控制 | E2、U-G001…044 |
| 新 Sobel 的窗口交接 | 在 top 内维护合法 q/r，接高斯实际输出，实例化独立窗口及复用 Sobel；原输入元数据仍交控制器检查，不能用修正后的坐标掩盖输入错误 | D4、E3、MD/HD |
| 方向 gradient_direction_pair | 组合逻辑做符号扩展、绝对值和范围检查；四级寄存器依次检查、移位加法、求比较量、判方向；使用 424/1024 整数比较；错误另占保持槽，flush 不丢错误 | E3、U-D001…049 |
| 分支 canny_fork_pair | 一个保持寄存器加两个 pending 位；每个下游握手只清自己的位；两支完成才释放或同沿装下一组，关闭梯度输出时不等待该支 | E3、U-F |
| NMS 窗口 nms_window_pair | 两行 RAM 分 byte 平面保存原幅值/方向；受限地址、延迟读写、水平历史和补边各有责任；边框原幅值保持，交分类器决定边框输出 | E4、U-NW |
| 分类 nms_classify_pair | 第一拍锁中心、邻居、方向、阈值和坐标；第二拍用旧寄存器完成中心大于负向邻居且大于等于正向邻居的判断；强边 M>TH，弱边 TL<M≤TH，否则无边 | B、E4、U-NC |
| 控制器及 top | 控制器统一拥有本帧配置、计数、第一错误和完成状态；top 负责连接及必要适配，避免另一份完成状态；完成须数量/EOF/错误/流水空同时满足 | C、D、E1、C0/MD |

阅读顺序：本表 → 权威设计 D 的端口和直接交接 → E 对应模块的逐拍草图 → G 的独立测试 → 编码后的实际源码。更细的位宽、边界与错误优先级沿用权威设计，不凭本摘要重新定义。

所有模块共同规则：只在 valid 与 ready 同时成立时接收/交付；停顿保持有效数据及坐标等伴随信息；组合赋值完整，时序状态使用时钟沿非阻塞更新；复位清有效状态，RAM 不整片清零；配置按已定义的启动事件锁定。每一级具体 advance/flush 条件仍以 D/E 为准。

## 实现和验证次序

1. 先独立数学参考及高斯、方向、分支、NMS 窗口、分类 RTL，逐模块编译/仿真，比较数值、边界、气泡、反压、复位和错误恢复。
2. 接真实 R1 前端及控制器，做短链：检查像素数量、坐标、配置和有效信号对齐，再运行完整 1080p 流段场景。
3. 接图样/观察外壳，完成本批既有 230 个仿真场景及 12 个输入校验、3 个故意 fatal 退出码探针。故意 fatal 的预期失败不当算法失败，也不冒充普通 PASS。
4. 同一份冻结实现进入 Ti60F225/I3 四引脚、25MHz 工程，执行综合、接口检查、布局布线、时序审阅；按实际资源/时序结果优化。必要检查通过后生成、校验并登记 bit，停止实体操作。

前期只排除明显不可能的容量/端口结构；详细资源和性能依据实际实现测量。本批结果不能代替整包相机/DDR/HDMI、完整 Canny 和识别验收。
