一、概述 
Ti60F255I3-DK 采用的是易灵思的 Ti60F225 FPGA 为核心的开发验证平台。 
该验证平台包括 Ti60F225I3 FPGA, 一个 GE 口 ,HDMI 接收及 HDMI 发送和 16 位的
DDR3，两路 FPC MIPI 座子，并预留了一个 QSE 座子用于扩展 IO 和验证 MIPI 接口。 
 其中 GE 口都可以实现３速；HDMI 通过 FPGA 高速 IO 实现，可支持到 1080p60Ｈ
z；DDR3 采用的是 MT41J128M16JT-125，位宽为 16 位，数据速率最高 800Mbps，可
以满足各种高带宽需求。板上的 flash 是 8MB，采用的是 GD25LQ64，用于存储 FPGA
镜像，也可以存储用户数据。下图是各个外设在板上的分布情况。

2.1 简述 
demo 板采用的是易灵思钛金系列的 Ti60F225I3.易灵思钛金系列采用的 16nm 工艺，
它具有超低功耗、超小封装和超高性能等特性。

Ti60F22I3 有 60K 逻辑单元，尺寸是 10mm x 10mm，它支持 1.5Gbps􀀃LVDS 和 1.5G 
MIPI DPHY,可以外挂 800Mbps DDR3. 
 
2.2 电源部分 
Ti60F225 的电源有表中以下几路。核电压 VCC 是 0.95V。VCCA 是 PLL 的模拟供电电
压，为 0.95V；VCCAUX 是辅助供电电压，为 1.8V；VCCIO 是 HSIO 的 IO 供电电压，
支持 1.2V，1.5V 和 1.8V；VCCIO33 是 HVIO 的 IO 供电电压，最高支持 3.3V。

2.6 上电时序及复位 
Ti60F225I3 对上电时序有较严格的要求。上电时序如下，要保证 VCC 和 VCCA 先上
电，然后 VCCAUX 及 VCCIO 再上电，等所有电源上电稳定之后，再经过 tCRESET_N才可以
释放复位。 
 

===== PDF PAGE 13 =====

易灵思 FPGA 需要一个专门的复位，在各个电源稳定之后，在上升沿触发 FPGA 采集多
功能引脚状态，保证 FPGA 的正确配置。手动复位可以让 FPGA 重新加载 flash 中的程
序。 
在 Ti60F225-DK 上我们使用一个电压检测芯片，用于检测 IO 电压；为了保证正确的复
位时钟，在在电压检测芯片后配上了 RC 复位电源。 
另外还支持手动复位。

2.7 JTAG 下载 
2.7.1 板载下载器 
 Ti60F225-DK 上提供了板载下载器，下载芯片为 FT4232HL，所以客户无需外接下载
器。这样既可以保证程序下载的稳定，也可以让连线的简洁：用户只需要一根TypeC 
USB 线就可以实现供电、下载和 UART；同时也可以有效的降低客户的采购成本。 
 
 
2.7.2 外接下载器 
Ti60F225-DK 还预留了外接下载器的座子。操作方法如下： 
（1） 把 J8 的 Pin 9(FTDI_RST)与 GND 短接，确认 FT4232DL 的 IO 处于高阻态。 
（2） 通过 J8 的 TDO,TCK,TMS,TDI,VCC_3V3 和 GND 与外部下载器连接。

2.8 编程方式 
Ti60F225-DK 默认通过连接 USB，然后通过 JTAG Bridge 编程 flash。但其实也可以去
验证 AS 模式。操作如下： 
（1） 把 J8 的 CRESET_N 连接 GND 或者手动按住 CRESET_N 按键； 
（2） 通过外部下载器连接 J6 连接座了的 VCCIO1A,SS,CDI0,CDI1，CCK 和 GND； 
（3） Programmer 中选择 Active mode； 
（4） 如果上电时通过下拉 SS，确保其实为低电平，则跳过（3）选择 Passive Mode
验证 PS 模式。

3.1、RGMII 
RGMII(Reduced Gigabit Media Independant Interface),精简 GMII 接口。相对于 GMII 相
比，RGMII 具有如下特征： 
TX_ER 和 TX_EN 复用，通过 TX_CTL 传送 
RX_ER 与 RX_DV 复用，通过 RX_CTL 传送 
1 Gbit/s 速率下，时钟频率为 125MHz 
100 Mbit/s 速率下，时钟频率为 25MHz 
10 Mbit/s 速率下，时钟频率为 2.5MHz 
信号定义如下： 
信号名称 描述 方向 
TXC 发送时钟 MAC→PHY 
TX_CTL 发送数据控制 MAC → PHY 
TXD[3:0] 发送数据 4bit MAC → PHY 
RXC 接收时钟 PHY → MAC 
RX_CTL 接收数据控制 PHY → MAC 
RXD[3:0] 接收数据 4bit PHY → MAC 
MDIO 管理数据 双向 
MDC 管理数据时钟 MAC → PHY 
RGMII 的 TXC/RXC 时钟为 125Mhz，为了达到 1000Mbit 的传输速率，TXD/RXD 信号
线在时钟上升沿发送接收 GMII 接口中的 TXD[3:0]/RXD[3:0]，在时钟下降沿发送接收
TXD[7:4]/RXD[7:4],并且信号 TX_CTL 反应了 TX_EN 和 TX_ER 状态，即在 TXC 上升沿发
送 TX_EN,下降沿发送 TX_ER，同样的道理试用于 RX_CTL， 
TX_ER（transmit coding error）：TX_ER 同步于 TX_CLK，在数据传输过程中，如果
TX_ER 有效超过一个时钟周期，并且此时 TX_EN 是有效的，则数据通道中传输的数据
是无效的，没用的。注：当 TX_ER 有效并不影响工作在 10Mb/s 的 PHY 或者 TX_EN 无
效时的数据传输。在 MII 接口的连线中，如果 TX_ER 信号线没有用到，必须将它下拉
接地。

1、DDR 的容量大小 
 
先看下 micron 公司对 DDR3 命名的规则： 
 
1、meg 的含义： 
内存中 Meg 的含义：Meg 就是兆的含义，即 1000,000. 
MT41J128M16 – 16 Meg x 16 x 8 Banks 的含义： 
表示方法是：每个逻辑 BANK 的单元格数×每个单元格的位数(芯片数据位宽)×逻辑
BANK 数量，即每个逻辑 BANK 的单元格数为 16 兆，每个单元格的数据位是 16bit，逻
辑 BANK 的数量为 8 个。这样 MT41J128M16 就是 256MB(2Gb)的容量。

7.1 SOFT MIPI 硬件设计原则  
初识易灵思可能有些点要注意。这里我们说明下钛金系列 MIPI 的设计规则 。 

===== PDF PAGE 30 =====
 
 
29 
钛金系列 FPGA 支持 CSI RX/TX 和 DSI TX,速率最高能达到 1.5Gbps(不同速率等级的器
件是有差异的要具体确认。) 
 
（1）MIPI 的 bank 电压是 1.2V 的。 
（2）一定要参考 pin out 文件。这里以 Ti60F225 为例。如下图。 
pin out 文件 MIPI RX Function 一栏就是 MIPI RX 可以使用的情况。 
对于 MIPI RX 信号，数据定义为 RX_DATA_P/Nx_Iy，x 是指每个组中的数据线信号编
号。y 是指 MIPI 组，每个组是 4lane 或者 8lane 的，如下图第 8 组就是 4lane MIPI
组，包括 5 个差分对；第 7 组就是 8lane MIPI 组，包括 9 个差分对。 
每组 MIPI 中的时钟叫 RX_CLK_Iy，它的位置是固定的。但数据是可以交换的。 
（3）对于 MIPI TX 则没有太多要求，只要放在 MIPI bank 即可。 
(4)当使用 HSIO 为 GPIO,LVDS 或者 MIPI 时，要确保 GPIO，LVDS 和 MIPI 之间要隔出
一对未分配的 IO，这样可以减少开关噪声，如果没有隔开的话软件也会提示错误。

以太网首部 
以太网首部包括三部分：目的 MAC 地址，源 MAC 地址和类型。 
 
目的 MAC 地址：6 字节，存放目的设备的物理地址，即 MAC 地址  
源 MAC 地址：6 字节，存放发送端设备的物理地址  
类型：2 字节，用于指定协议类型，常用的有 0800（hex）表示 IP 协议；0806 表示 ARP
协议；8035 表示 RARP 协议 。数据先传输高字节,再传输低字节. 
数据：46 到 1500 字节，最少 46 字节，不足需要补全 46 字节，例如 IP 协议层就包含
在数据 部分，包括其 IP 头及数据。  
FCS：帧尾，4 字节，称为帧校验序列，采用 32 位 CRC 校验，对目的 MAC 地址字段到数
据字段进行校验。 
 
进一步扩展，以 UDP 协议为例，可以看到其结构如下，除了以太网首部的 14 字节，
数据部分包含 IP 首部，UDP 首部和应用数据共 46~1500 字节。

用于控制 IP 数据报是否允许分片。如果 DF 位被设置为 1，表

包，并向源主机发送一个 ICMP 差错报告报文，告知源主机数据
包因为不能分片而被丢弃。如果 DF 位为 0，则表示允许对数据
报进行分片。

后一个分片或者该数据报没有进行分片。例如，一个大的 IP 数

UDP 协议 
UDP 是 User Datagram Protocol（用户数据报协议）的英文缩写。UDP 只提供一种基本
的、低延迟的被称为数据报的通讯。所谓数据报，就是一种自带寻址信息，从发送端走到
接收端的数据包。UDP 协议经常用于图像传输、网络监控数据交换等数据传输速度要求比
较高的场合。 
 
UDP 协议的报头(UDP 首部)格式：  
 
UDP 报头由 4 个域组成，其中每个域各占用 2 个字节，具体如下： 
 
 
源端口：源端口号。在需要对方回信时选用。不需要时可用全0。 
目的端口：目的端口号。这在终点交付报文时必须要使用到。 
长度：UDP 用户数据报的长度，对应 UDP 首部及应用数据的字节长度，其最小值是 8（仅
首部） 。 
校验和：检测 UDP 用户数据报在传输中是否有错。有错就丢弃。

三、UDP 校验和计算 
UDP 计算校验和的方法和 IP 数据报首部校验和的方法相似。不同的是：IP 首部校验和只
校验 IP 首部，但 UDP 的校验和是把首部和数据部分一起都检验。 
 
UDP 的校验和需要计算 UDP 首部加应用数据部分，并且还需要加上 UDP 伪首部。这个伪
首部指源地址、目的地址、UDP 数据长度、协议类型（0x11） ，协议类型就一个字节，但
需要补一个字节的 0x0，构成 12 个字节。伪首部+UDP 首部+数据一起计算校验和。 
 
UDP 检验和的计算方法是： 
 
1. 从“伪头部”开始，按每 16 位当作一个数，逐次求和，最终得出一个 32 位的数； 
2. 如果这个 32 位的数的高 16 位不为 0，则进行“回卷”操作。也就是将这个 32 位数
据的高 16 位与低 16 位相加，得到一个 32 位的数； 
3. 重复第 2 步直到高 16 位为 0。 
4. 最终，将低 16 位取反，得到校验和，填入 checksum 字段中 
 
差错检验 
当接收到 UDP 报文时，需要如何检验其正确性？方法就是将 UDP 报文中包括校验和在内
的，所有的 16 位的数相加，如果低 16 位全为 1，则没有出错。否则表明该分组中出现了
错误。 
需要注意，UDP 对差错具有一定的校验能力，但缺少差错恢复的能力

并发调试（Enable Concurrent Debugging） 
自 Efinity RISC-V 嵌入式软件 v2025.2 版本起，新增了一种调试流程，称为「并发调试」
（concurrent debugging）。在并发调试模式下，可通过单个 FTDI JTAG 接口，同时进行 
RTL 调试与 RISC-V 内核调试，当然两者使用不同的 USER TAP. 
 
你需要安装以下软件： 
● Efinity 软件 v2025.2 版本 
● Efinity RISC-V 嵌入式软件集成开发环境（IDE）v2025.2 版本 
 
若要使用并发调试功能，请遵循以下步骤： 
1. 在「HBR」选项卡中，启用 efx_soc IP 配置里的「联合调试（Co-Debug）」
选项。 
2. 在 Efinity 调试向导（Efinity Debug Wizard）中，配置信号并编译工程。 
3. 下载 bit 文件。

5. 右键单击「group.launch」文件，选择「运行 / 调试（Run/Debug）」。 
6. 打开调试器（Debugger） ，先启用「共享（Shared） 」选项，再连接connect 
debugger 
7. 使用调试器执行 RTL 调试。 
你可同时进行两类调试操作，二者互不干扰。 
注意：联合调试（Co-Debug）仅支持 FPGA 的 JTAG 用户测试访问端口（JTAG User 
TAP interface） 。启用联合调试后， 「软件调试端口（Soft Debug Tap） 」选项将隐藏；
