## 整体架构与范围

目标结构：相机初始化/CSI → 官方 DDR 帧缓存/CVO → 已校色的去马赛克 → 自研算法适配层 → 原 HDMI 编码器。

原自研架构是采集整帧 → 算法/识别 → 完成发布 → 显示，原图也等算法。旧版还改过 PLL/DDR 时钟与复位依赖。此次保留当前 v7 时钟、DDR、CSI、扫描和已修正 RAW 顺序，算法只能影响显示内容，不能停止视频时序。

完整迁移分为三个硬件检查点：
1. 本次：原图、灰度、中值、Sobel 阈值和彩色边缘叠加；原 R1 算法直接复用。
2. 后续：按键控制/阈值和冻结；全帧 Canny 的独立存储服务与结果发布。完整 Canny 保留高斯、梯度、NMS、双阈值、滞后连接，不能用单次邻域近似冒充。
3. 后续：圆/矩形识别与同帧标注，采集/处理/显示帧率分别测量。

本次不将尚未接入的 Canny、识别或按键宣称完成；不把旧帧任务调度器整体搬回 v7。不新增工具、保护 IP、引脚或时钟约束。

## 行为与接口契约

- REQ-1：输入和输出都是 1920×1080 双像素扫描，74.25 MHz，同域上升沿，无输入反压。像素 0 在低 24 位，各像素为已验证显示意义的 RGB888；旧 debayer 的通道名称不作为颜色依据。
- REQ-2：复用 rgb_to_y_pair、window3x3_pair、line_store_pair、median9_pair、sobel_pair、frontend_frame_pair。灰度=(77R+150G+29B+128)>>8，3×3 replicate 边界，中值九样本，Sobel L1 严格大于 11bit 阈值，默认 256。
- REQ-3：保留独立扫描和原图；缓存算法结果，以原图的帧号/行/像素位置读取，不用算法 valid 生成 HS/VS/DE。未有对应完整结果行时回退同位置原图，记录故障；不使用陈旧结果行。
- REQ-4：帧开始锁定模式、阈值、中值开关。算法每帧重启，垂直消隐消化末行 replay；输入不能接收时取消本算法帧，下一帧恢复。
- REQ-5：显示模式 0 原图、1 灰度、2 中值灰度、3 二值 Sobel、4 红色边缘叠加、5 五个竖区比较。首个 bit 默认 5，从左至右依次原图/灰度/中值/边缘/叠加；保持原坐标与分辨率，不缩放。
- REQ-6：移除旧细线/色卡覆盖，使整幅输入都是实际相机内容；保留 RAW 行奇偶计数和白平衡。

适配模块 v7_algorithm_video_pair：输入 clk/rst、in_vs/in_hs/in_de/in_rgb[47:0]、cfg_mode[2:0]/cfg_threshold[10:0]/cfg_median_enable；输出同步的 out_vs/out_hs/out_de/out_rgb[47:0] 与 sticky_fault。支持偶数 W=4..1920、H=3..1080，HTOTAL 是双像素总时钟数，生产为 1100。

原图及同步通过一个循环 RAM 固定延迟四行，另有同步读与输出寄存器延迟；确切拍数由仿真核实后写入交付。结果按行号模 8、列组索引存入独立 RAM；行完成标记携带完整帧号和行号。四行延迟大于两个 3×3 窗口、流水线及行尾等待的预计最坏延迟，读前须匹配完整行标签。RAM 不清零，启动填充计数/有效标签隔离旧内容。原图持续写读，结果侧只有算法写和显示读，无新增 DDR 仲裁。

HDMI fast/slow serializer 保留，新增延迟只在 74.25 MHz 双像素域。沿用原 CDC/PLL 风险边界，不能由本算法单域测试推定整机时序正确。

## 实施与验证

1. 保存基线、实际复用文件和授权证据；在独立 work/active/track4_v7_algorithm_bridge_001_20261018 实现。
2. RTL 对照独立 Python 数值参考，覆盖 RGB 通道/双像素顺序、全六模式、replicate 四边角、噪声、中值、Sobel 严格阈值、动态配置帧边界、复位及帧间隔。
3. 至少一个完整 1920×1080 序列，核对每行每帧数量、同步固定延迟、结果行命中、输入无反压；注入算法未就绪/格式中断时确认原图及同步继续。
4. Efinity 综合、接口、布局布线、setup/hold 及新增告警审查；通过才生成/登记 bit。
5. 人工验证：五区都有实时变化，灰度中性、中值去噪、边缘轮廓和红色叠加位置一致，HDMI 仍 1080p60。此前约 12.66 fps 仅属于相机基线实测，不预先称新版本处理帧率已验证。
