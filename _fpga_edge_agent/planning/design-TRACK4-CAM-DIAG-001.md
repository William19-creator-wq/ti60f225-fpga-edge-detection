## B. 整体可观察行为

新增灯为粘滞标志：自本次逻辑复位以来看到对应事件就亮，保持至下次复位。亮灯表示“曾发生”，不表示持续帧率或端到端图像正确。逻辑高点亮。

| REQ / 灯 | 人能看到的含义 | 引脚 | 事件/来源 |
|---|---|---|---|
| R0 / D0 | 保留 DDR 校准后的原心跳 | P13 | 原 `cal_done ? cnt[24] : 0` |
| R1 / D1 | 至少一次写字节观察到 ACK | N13 | I²C 字节完成时从 SDA 收到应答位 0 |
| R1 / D2 | 至少一次写字节观察到 NACK | G3 | 同一完成事件的应答位为 1 |
| R2 / D3 | 164 项配置事务序列走完 | N2 | 最后一项实际 `wr_done` |
| R3 / D4 | 曾收到 CSI 的 VS 标志 | G4 | 原始接收端 `w_mipi_rx_vs` |
| R3 / D5 | 曾收到 CSI 的有效像素标志 | E1 | 原始接收端 `w_mipi_rx_de` |
| R4 / D6 | 曾接受 DDR 写数据拍 | E2 | `s_axi_wvalid && s_axi_wready` |
| R4 / D7 | 曾接受 DDR 读数据拍 | M2 | `s_axi_rvalid && s_axi_rready` |

R5：诊断只能增加旁路观察，不能反馈改变原事务、相机输出引脚、配置、时钟和复位行为。R6：新产物必须有独立路径、构建证据和哈希，下载日志与随后人工灯态关联。

正常样例：I²C 字节全部得到 ACK、配置走完、持续收到帧和像素、DDR 收发数据，则 D0 闪，D1/D3–D7 亮，D2 灭。边界样例：所有写字节均 NACK，则 D2 可亮、D1 灭，D3 仍可能亮，不能误报“配置成功”。无相机像素但显示仍读 DDR 时，D4/D5/D6 可灭、D7 可亮；这与目前噪点现象相容，但不是预先认定现场灯态。

- IF-I2C：M1→M3→M4 的两个标志在 `CLK_5M` 域。事件是 `core_en && done && wr && !i2c_al`；采 `irxack`，不用 Wishbone 的 `wb_ack_o` 或复位默认的 `rxack`。M1沿用本模块 `arst_i` 低有效异步复位与 `wb_rst_i` 高有效同步复位；本实例 `arst_i=1`、`wb_rst_i=~i2c_rst_n`。初始化期间清零，字节完成后保持。
- IF-SEQ：M2→M3→M4 的标志同为 `CLK_5M` 域、现有低有效 `rst_n=i2c_rst_n`。仅固定当前 `DATA_LENGTH=164` 的写表；`S4` 中旧 `cnt=163` 且旧 `wr_done=1` 才置位。最后一项是 ROM 索引 A3，对应寄存器 3221，不能把开始发送或 I²C 控制核 `init_done` 当完成。
- IF-CSI：M4 在 `i_mipi_rx_pclk` 上升沿采原 1 位 VS/DE，分别保持“见过高”；用现有像素域 `w_mipi_rx_pclk_arstn` 清零。标志不参与像素接受，无反压，不复制像素数据。
- IF-AXI：M4 在 `core_clk` 上升沿采现有 1 位 valid/ready，每路只有两者同时为 1 才记录。新增仅供两个观察寄存器使用的两级异步拉低/同步释放复位，源为 `w_arstn`；不改 DDR 控制器的复位连接。
- IF-LED：已有输出模式、端口、引脚及电平标准不变，原理图均为 LED 驱动，和 SW0–SW3 分开。各域标志只驱动各自 LED，域间不传递事务、不产生控制反馈；人读灯允许各位先后变化，不承诺原子快照。
- 已检查原顶层仅 `led[0]` 有驱动，其他七位可使用。增加输出时保持本文件其他具名实例兼容；未被顶层实例化的旧包装器不纳入业务修改。
- 预算：新增不超过 16 个 FF、64 个 LUT；新增 RAM/DSP 为 0；这是估计，实际以报告差值为准。无新缓存或数据吞吐限制，旁路扇出仍需 PNR/STA 检查。

## E–F. 中文操作草图与 RTL 契约

1. **I²C 应答**：复位先把两灯记录清零。每个 5MHz 上升沿，只有原字节控制器宣布写字节结束、核已启用且当前未仲裁丢失时，读取该字节的 `irxack`；应答位为 0 就保留 ACK 记录，为 1 就保留 NACK 记录。其余周期保留旧状态。两灯允许同时亮。不开启重试，不提前或延后现有控制命令。
2. **配置表结束**：每沿查看原状态和原计数；只有正在等最后一项、该项 `wr_done` 到达，才把结束记录置 1。该沿原 FSM 仍按原逻辑推进，诊断记录不决定推进。中途复位取消记录，NACK 不自动阻止 D3。
3. **MIPI 活动**：像素域复位清零两记录；在本域每沿分别看 VS 和有效像素标志，见 1 后保持。VS 灯不是完整帧计数器，DE 灯不验证 RAW 内容或行宽。
4. **DDR 活动**：复位拉低时立即清零诊断复位两级；释放后连续两个 core 时钟逐级放行，观察逻辑在随后上升沿才开始记握手。valid 单独为 1 或 ready 单独为 1 不亮灯。读写记录互相独立，绝不驱动 ready/valid。
5. **人工读取**：下载后等待约 5 秒，按板上 D0→D7 编号记录。新标志记录本次启动以来的事件；必要时只按 SW0 清除并重跑。现有程序的自动复位会清除所属域记录，因此不同域的灯态不应解读为同一帧快照。

所有诊断值为 1 位无符号；诊断状态初值/复位值为 0，时序更新用非阻塞赋值。M1 的旧 `done/irxack/wr` 在采样沿前有效，字节控制器前一沿同时登记应答与完成，父模块下一沿采样；原命令位随后清零不影响该次观察。新增代码不加入原 IP 的仿真 `#1` 延时。

无软件算法或 C++/RTL 数值映射，相关契约 N/A；没有像素缩放、截断、帧重排、新配置或新存储。现有 I²C/视频/DDR 的 valid、停顿、存储及输出身份均不改变。D1–D7 在事件采样沿后更新，供人观察，不作为同步外设数据。对原 I²C 控制块内部复位形式原样沿用，诊断不修复其原有复位设计。
