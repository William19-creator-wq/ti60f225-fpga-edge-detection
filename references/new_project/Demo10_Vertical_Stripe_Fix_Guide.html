Demo10 竖条纹与线条断续问题修复指南

适用工程：Ti60F225 DemoBoard v4 / SC431HAI to HDMI Demo

作者：LeoXuanyi

1. 问题判断

从图像特征和工程代码判断，主要问题是 CSI-2 输出的四个 RAW10 像素被以相反顺序送入 DDR 帧缓存。这样会导致每四个像素内部左右翻转，连续斜线呈现规律性的锯齿、短竖条或虚线。

照片中还可能包含手机拍摄显示器产生的细密摩尔纹。判断时应以肉眼观察或 HDMI 采集卡抓取的原始帧为准。

主要修改文件：

E:\Efinix_FPGA\boards\Ti60F225_DemoBoard_v4\10_Ti60f225_sc431hai2hdmi_demo\Ti60f225_sc431hai2hdmi_v1\rtl\ti60f225_oob_top.v

2. 修正 RAW10 四像素顺序

在 frame_buffer 实例附近找到当前代码：

.vin ({
    w_mipi_rx_data[39:32],
    w_mipi_rx_data[29:22],
    w_mipi_rx_data[19:12],
    w_mipi_rx_data[9:2]
}),

替换为：

.vin ({
    w_mipi_rx_data[9:2],
    w_mipi_rx_data[19:12],
    w_mipi_rx_data[29:22],
    w_mipi_rx_data[39:32]
}),

CSI RX 的 RAW10 像素排列为：

像素数据位取8位后的数据位
Pixel 1pixel_data[9:0][9:2]
Pixel 2pixel_data[19:10][19:12]
Pixel 3pixel_data[29:20][29:22]
Pixel 4pixel_data[39:30][39:32]

工程中的 DDR 写入和读出逻辑按高位数据先输出。原代码实际产生以下顺序：

正常：1 2 3 4 | 5 6 7 8
原来：4 3 2 1 | 8 7 6 5

因此水平线不一定明显异常，但斜线会按四像素周期出现锯齿。这是本次问题的最高优先级修正项。

3. 修正标准1080P时序

找到图像分辨率和消隐参数，将其改为标准 1920×1080@60Hz：

localparam MAX_HRES = 12'd1920;
localparam MAX_VRES = 12'd1080;

localparam HSP      = 8'd44;
localparam HBP      = 8'd148;
localparam HFP      = 8'd88;

localparam VSP      = 8'd5;
localparam VBP      = 8'd36;
localparam VFP      = 8'd4;

标准总时序为：

水平：1920 + 88 + 44 + 148 = 2200
垂直：1080 + 4 + 5 + 36 = 1125

4. 修正帧缓存水平同步宽度

帧缓存输出端每个时钟处理两个像素，因此所有水平参数都应除以2。找到：

.H_FRONT_PORCH (HFP/2),
.H_SYNC        (HSP),
.H_VALID       (MAX_HRES/2),
.H_BACK_PORCH  (HBP/2),

.V_FRONT_PORCH (VFP),
.V_SYNC        (VSP),
.V_VALID       (MAX_VRES),
.V_BACK_PORCH  (VBP),

将 H_SYNC 修改为 HSP/2：

.H_FRONT_PORCH (HFP/2),
.H_SYNC        (HSP/2),
.H_VALID       (MAX_HRES/2),
.H_BACK_PORCH  (HBP/2),

.V_FRONT_PORCH (VFP),
.V_SYNC        (VSP),
.V_VALID       (MAX_VRES),
.V_BACK_PORCH  (VBP),

修改后的双像素时钟域水平参数为：

有效区：960
前肩：44
同步：22
后肩：74
总计：1100个双像素时钟

5. 修正2像素转1像素的行首相位

原来的 vid_cnt 自由翻转，没有在复位或每行消隐期间重新对齐。将原有的像素拆分逻辑整体替换为：

reg vid_cnt;

reg [7:0] hdmi_tx_rdata;
reg [7:0] hdmi_tx_gdata;
reg [7:0] hdmi_tx_bdata;

reg hdmi_tx_vs;
reg hdmi_tx_hs;
reg hdmi_tx_de;

always @(posedge hdmi_tx_slow_clk or negedge vid_rst_n)
begin
    if (!vid_rst_n)
    begin
        vid_cnt       <= 1'b0;

        hdmi_tx_rdata <= 8'd0;
        hdmi_tx_gdata <= 8'd0;
        hdmi_tx_bdata <= 8'd0;

        hdmi_tx_vs    <= 1'b0;
        hdmi_tx_hs    <= 1'b0;
        hdmi_tx_de    <= 1'b0;
    end
    else
    begin
        hdmi_tx_vs <= rgb_vs;
        hdmi_tx_hs <= rgb_hs;
        hdmi_tx_de <= rgb_de;

        // 在每行消隐期间重新对齐到第一个像素
        if (!rgb_de)
        begin
            vid_cnt       <= 1'b0;
            hdmi_tx_rdata <= 8'd0;
            hdmi_tx_gdata <= 8'd0;
            hdmi_tx_bdata <= 8'd0;
        end
        else
        begin
            if (!vid_cnt)
            begin
                // 第一个像素
                {
                    hdmi_tx_rdata,
                    hdmi_tx_gdata,
                    hdmi_tx_bdata
                } <= rgb_datax2[47:24];
            end
            else
            begin
                // 第二个像素
                {
                    hdmi_tx_rdata,
                    hdmi_tx_gdata,
                    hdmi_tx_bdata
                } <= rgb_datax2[23:0];
            end

            vid_cnt <= ~vid_cnt;
        end
    end
end

这样每行有效视频开始时都固定从 rgb_datax2[47:24] 开始，避免奇偶像素相位随消隐长度或复位时刻发生变化。

6. 检查 DVI Encoder 信号连接

当前代码对 R/B 和 HS/VS 进行了交换：

.i_bdata (hdmi_tx_rdata),
.i_gdata (hdmi_tx_gdata),
.i_rdata (hdmi_tx_bdata),

.i_hs    (hdmi_tx_vs),
.i_vs    (hdmi_tx_hs),
.i_de    (hdmi_tx_de),

建议按正常对应关系修改：

.i_bdata (hdmi_tx_bdata),
.i_gdata (hdmi_tx_gdata),
.i_rdata (hdmi_tx_rdata),

.i_hs    (hdmi_tx_hs),
.i_vs    (hdmi_tx_vs),
.i_de    (hdmi_tx_de),
如果修改本项后显示器完全无法锁定，而修改前能够稳定显示，应暂时恢复这一项。加密的 DVI Encoder 或原工程信号命名可能存在特殊约定。RAW10 像素顺序、1080P时序和行首相位修正仍应保留。

7. 增加 CSI 输入诊断信号

在 CSI RX 实例前增加：

wire [15:0] mipi_word_count;
wire [5:0]  mipi_datatype;
wire [3:0]  mipi_pixel_per_clk;

把原来悬空的端口：

.word_count     (),
.datatype       (),
.pixel_per_clk  (),

改为：

.word_count      (mipi_word_count),
.datatype        (mipi_datatype),
.pixel_per_clk   (mipi_pixel_per_clk),
.pixel_data      (w_mipi_rx_data),
.pixel_data_valid(w_mipi_rx_de),

使用 Efinity Debugger 观察时，1920像素 RAW10 的正常结果应接近：

信号预期值说明
mipi_datatype6'h2BCSI-2 RAW10 数据类型
mipi_pixel_per_clk4每时钟4个像素
mipi_word_count24001920 × 10 ÷ 8

8. 临时绕过 Debayer

如果完成前述修改后仍有周期性条纹，可暂时绕过 Debayer，将两个 RAW 像素直接显示为灰度图。

在 rgb_datax2 声明附近加入：

localparam DEBUG_BYPASS_DEBAYER = 1'b0;

wire [47:0] raw_gray_datax2;

assign raw_gray_datax2 = {
    ch0_g, ch0_g, ch0_g,
    ch0_b, ch0_b, ch0_b
};

wire [47:0] display_datax2;

assign display_datax2 =
    DEBUG_BYPASS_DEBAYER ? raw_gray_datax2 : rgb_datax2;

在2像素转1像素代码中，将：

rgb_datax2[47:24]
rgb_datax2[23:0]

改为：

display_datax2[47:24]
display_datax2[23:0]

需要进行灰度旁路测试时设为：

localparam DEBUG_BYPASS_DEBAYER = 1'b1;
测试结果判断
灰度图仍有周期性断线重点检查 CSI 像素顺序、DDR打包和2转1串行化。
灰度图连续，Debayer彩色图断续检查 Bayer 阵列格式、裁剪起点和镜像/翻转设置。
灰度图和彩色图都连续RAW10 四像素顺序修正已经解决主要问题。

测试结束后恢复：

localparam DEBUG_BYPASS_DEBAYER = 1'b0;

9. 第一轮不要修改的文件

  • rtl/debayer/debayer_top_2to1.v
  • rtl/debayer/raw_to_rgb.v
  • 生成的 csi_rx_controller.sv
  • DDR控制器生成文件和加密IP源码

先确认像素顺序、1080P时序和2转1相位。只有灰度旁路正常而 Debayer 输出异常时，才需要进一步调整 Bayer 相位。

10. 推荐实施顺序

  1. 1 修正 RAW10 四像素顺序。
  2. 2 重新编译并下载位流，观察斜线是否恢复连续。
  3. 3 修改标准1080P时序以及 HSP/2。
  4. 4 修改 vid_cnt 行首对齐逻辑。
  5. 5 检查 DVI Encoder 的 RGB 和 HS/VS 对应关系。
  6. 6 若仍异常，再启用 Debayer 灰度旁路。
最关键的修正是将 .vin 的像素排列改为 Pixel1、Pixel2、Pixel3、Pixel4。RTL修改后只需要重新编译并下载新的 .bit 位流，不需要重新生成 ELF。
