# TRACK4-ALGORITHM-ROUTE-001：算法优先路线 v1

2026-10-04；按[PLAN_TEMPLATE](PLAN_TEMPLATE.md)。当前路线为 GLOBAL_DESIGN；首批实现对象另见[R1 设计 v1](design-TRACK4-ALGORITHM-R1-001.md)。完整算法路线、完整十一功能与硬件验收均未完成。

## 通用计划字段

- Goal：按编码规范先完成不依赖具体外部存储器件的算法，再以独立 Ti60F225/I3 工程获得仿真、综合、布局布线、合理引脚/时序及 bit 证据。
- Current state：已有大量算法设计，尚无这次业务实现。FRONTEND v1 是独立单时钟前端；Canny、识别及整机父稿尚未全部 READY。
- Target state：各算法有真实源码/参考/测试、中文操作说明与双向追踪；每个已批准硬件范围有 Efinity 实际报告和 bit。
- Gap：批准前不生成业务源码/TB；完整闭包与识别需算法级存储/数值边界；现有数据库运行前置未满足。
- Assumptions：软件目标 Ti60F225/I3；生产 1920×1080。小图只调试边界。实际相机和 HDMI 接入放在算法之后。
- Open questions：R2…R5 的完整局部设计、真实资源/吞吐/质量待完成；不将这些当 R1 的阻塞。
- Dependencies：v0.2、R1 新基线、既有 Efinity/Questa/Python；不以停止关注的器件模型、PHY、校准或 IP 预检作为当前前提。
- Milestones：R1 独立流式核 → R2 Canny流段/显示算术 → R3几何数值核 → R4完整闭包/识别 → R5资源性能与集成。
- Detailed steps：整体行为→模块/交接→局部中文草图→验证/追踪→指定范围批准→编码→真实工具验证→按代码回核文档。
- State transitions：路线 GLOBAL_DESIGN；每批独立 READY/批准/实现/验证，不升级整机或正式 H/A/R 状态。
- Artifacts and hashes：[新目录入口](../experiments/track4_algorithms_20261004/README.md)；设计/基线/审查/验证分类，代码只在 work。
- Validation：逐位数值、时间协议、综合、PNR/STA、bit分别登记；图样外壳不冒称相机/HDMI已完成。
- Failure handling：错误留日志、停止受影响阶段，不删失败、不改期望、不用历史 pass。
- Human approval gates：v0.2 §10.4及原工作副本/构建审批；数据库例外若需要须明确批准，不能默认绕过。
- Rollback：保留旧稿，只在控制面新增新路线；撤回不碰原 HDK 或旧工作任务。
- Completion criteria：每个明确范围有实测证据，完整十一项不能由 R1 或算法仿真替代。

## A. 用户更正与边界

用户原话：“不要再理会V4 板上 2Gb/x16 DDR3 器件有關的东西, 优先按照編码規范重新規划路线來完成与它无關的算法設計, 井能夠在efinity上跑起來, 能綜合, 仿真, 并且可以布线布局, 引脚和时序约束合理, 只是在生成比特流之后的步骤你暂时不用理会”。

据此，停止相关器件模型搜索、下载请求、校准规划和刚形成的 DDR/IP 预检审批；旧资料只作历史保留，不成为新路线的串行前置。T4-A3 当前 DEFERRED_BY_USER，不标完成，也不擅自永久删除原十一项。其他算法继续设计/实现。

设计批准与本次路线调整不同：用户已授权本次重新规划，但尚未批准新形成的 R1 v1/范围/基线。

## B. 整体行为与完成观察

AR-REQ01：可暂停 RGB888 输入→全尺寸灰度/中值/Sobel、同坐标结果和真实终态。
AR-REQ02：Canny 仍须 Gaussian→新梯度→方向→NMS→双阈值→精确八邻域闭包，分类图不是最终 Canny。
AR-REQ03：圆/任意旋转矩形的数学、候选/核验/标注与每类 P/R≥95%、同类 IoU≥0.5 一对一评价保持；已撤回尺寸/数量/遮挡/噪声界限不重新强加。
AR-REQ04：算法不绑定某款物理存储器；需要历史数据时明确逻辑容量、唯一拥有者、提交可见性和失败语义。
AR-REQ05：真实工程必须保留被测算法，核查层级/资源/时钟/pin/所有有效路径；虚拟 IO 或常零顶层不能充作可用 bit 证据。
AR-REQ06：到 bit/日志/摘要登记停止；实体下载、烧写、观察和比赛视频暂不执行。

正常：R1 在 1080p 同一输入上比较 median 开关和阈值，按坐标逐像素相等，独立工程使用完整核。
反例：若只综合 Gaussian/NMS 并输出分类，T4-A4 仍未完成；若只看 LED 摘要相同，不能代替逐位比较；若小图连接通过，不能标 1080p/资源通过。

## D. 算法接口与组合检查路线

流式连接沿 R1 的 job/像素/终态握手和锁定身份；有反压的流不能直接连接不可暂停相机。窗口各自按有限图复制边界，中心坐标是结果身份。

彩色覆盖须同时取得同(job,x,y)的原 RGB 和 edge；FRONTEND 现 FO 只有 M/edge，R1 不实现通用彩色对齐。R2 必须另定有限保持/中心携带方案；固定物理拍移位在停顿时不相容。

全帧算法层只定义 CLASS/EDGE/GRAD/POINTS/QUEUE 等逻辑对象，不在当前路线讨论具体器件/PHY。引用现有 Canny 数学规则而不继承旧 917bit物理任务、grant、地址区、DDR生命周期。R4 新版本须冻结：容量/地址/端口延迟、阶段唯一拥有者、claim+入队原子性、forward可见性、取消时实际已接受义务排空、完整结束条件。可比较片上 bit-plane/分类重放与通用存储服务方案，未选择前不声称资源可实现。

1080p 旧 Canny 候选 CLASS2=518400 B，EDGE1=259200 B，GRAD32和QUEUE32各8294400 B；这些是逻辑工作量，不能全塞片上或以缩图掩盖。完整识别同样保留所有点/候选/覆盖/最终记录义务。资源利用率以实际有效吞吐/质量/面积比较，不以“填满资源”为目标。

## E. 各批中文操作草图

R1：核设计/运行范围→独立源码→窗口与算术单元→全图与时间回归→可观察外壳→25MHz真实工程→map/PT/PNR/STA→bit→登记和中文阅读；详见 R1 的 OP/测试。
R2：先锁数值→各邻域独立补边→同中心方向/幅值→NMS保存原外框幅值→双阈值→完整分类终态；对 overlay 另做原RGB/edge交接检查。
R3：接受 typed请求→先检查宽度/值域→全宽计算→收窄前检测→形成结果/拒绝→反压保持→实际消费后释放；不得把 A192 的 floor96/RNE97 误写成一份96bit结果。
R4：完整分类可见→种子/访问事实→每候选仅接纳一次或明确的单调迭代→精确终止→全图导出→独立识别→最终量化几何核验/同类去重→标注；未知存储部分保持 NOT_READY。
R5：实测瓶颈→比较候选资源/等待→仅按批准边界优化→重跑受影响测试/STA→冻结交付版本。改变数值/时间/存储边界先修订。
