## B. 可观察行为

- REQ-C1：上电全屏灰度，KEY3 每次有效按下循环 GRAY → MEDIAN → DIFF X8 → SOBEL → OVERLAY → SPLIT → COLOR → GRAY。原有模式0..5数值保持，新增6为差值。完整画幅、原始坐标，无缩放；时间先后比较需要固定镜头和场景，非同帧冻结。
- REQ-C2：差值=饱和到255的 abs(灰度−中值)×8，再复制到RGB。黑色表示数值相同，不代表画面丢失；输入无对应算法结果时回退彩色并显示等待标记。比较双方来自同帧同像素。
- REQ-C3：KEY1加32、KEY2减32，11位阈值0..2047饱和，初值256；同步消抖20ms（1485000个74.25MHz时钟），长按仅一次，复位时按住须先稳定释放。同拍两个按下事件抵消，不承诺不同时间按下抵消，不添加组合键功能。
- REQ-C4：所有控制在输入帧开始锁定；同沿按下更新在下一帧生效；不改变正在显示帧的算法。顶部32像素内显示模式和十进制阈值，字幕按同帧配置延迟，算法结果等待状态可见。阈值只影响边缘和叠加，不影响灰度、中值、差值。
- REQ-C5：按键不得改变 PLL/DDR/相机或停止 HDMI；基线四行+2拍固定延迟、故障原图回退与下一帧恢复保留。

## C. 模块和接口

原 RAW→DDR→debayer→v7_algorithm_video_pair→串行化/HDMI 数据链不变。新增 v7_algorithm_control：异步低有效按键→双触发器→稳定样本消抖→pending mode/threshold；使用 vid_clk_dvi2 和与桥接层相同的同步复位。旧 live_threshold_control 的 job_fire 置0，只使用 pending；桥接层现有 frame_boundary 负责锁定。

v7_algorithm_video_pair 的外部接口保持，参数增加 HUD_ENABLE 默认1；scan RAM 从54位到65位（增加同帧阈值11位），已有mode与VS/HS/DE/RGB位位置保持。pending增加y坐标；显示前组合调用 v7_algorithm_status_pixel 两像素实例，原输出寄存器保持，字幕不参与算法输入。HUD在x<320,y<32，仅小区覆盖。字形5×7、2倍显示，内容固定8字符模式名、T:和四位十进制阈值，状态小方块绿=有结果/橙=等待。

管脚仅增加三个3.3V LVCMOS输入并弱上拉，按已核实按键表增加peri节点；核对没有GPIO占用。SDC仅追加异步键到第一级同步器的false path，不切断同步器级间路径。映射网表复核两级结构和约束命中，现有时钟关系保持。

## D. 数值、时序、资源和组合检查

灰度/中值/Sobel仍复用先前位精确算法。差值先8位无符号比较后相减，>=32饱和255，否则左移3。HUD采用ASCII小字模，decimal0..2047有限常数除法；须检查新增组合路径时序。配置不是跨域总线，按键同步后与算法同域；HDMI双像素串行化路径保持。

新增RAM预算16块以内、逻辑预算3000 XLR，整机预计不超过25000 XLR/185 RAM，实际实现后记录。保证scan地址/循环深度不变，同帧结果有效性继续由完整行标签决定。故障时差值不使用旧RAM内容；字幕仅在DE内可见。复位清除配置/有效性，不清大RAM。
