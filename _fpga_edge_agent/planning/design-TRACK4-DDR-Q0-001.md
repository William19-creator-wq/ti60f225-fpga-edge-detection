触发是用户批准后的单次独立软件预检；输入是被冻结文件/工具/环境边界；输出是编译库、日志、优化设计单元（如成功）和限定报告。正常样例：全部身份相符→vendor 编译成功→DUT 编译成功→合法展开成功→Q0 有限通过。边界样例：DDR 顶层虽在旧整板 vlog 中编译成功，独立 vopt 却报告保护实现隐藏模块未解析→保留诊断，Q0 未通过，不能因为旧 CSI 报错而归咎或赦免 DDR。

终态仅一次：PASS_COMPILE_ELAB_FINITE、FAIL_TOOL_DIAGNOSTIC、ENV_FAIL、UNKNOWN_DIAGNOSTIC、ABORT_TIMEOUT、NOT_RUN_BASELINE_DRIFT 或 INVALIDATED。ENV_FAIL 仅用于有直接环境/许可证据的失败，不将所有工具报错冒称环境问题。结束时原来源漂移将已有结果标 INVALIDATED，保留原阶段结果和原因，不覆盖原日志。

## C. 职责、接口与组合检查

本卡没有新硬件模块。角色 QC（输入/范围 owner）承担 Q0-01；QE（既有工具调用 owner）承担 Q0-02/03；QR（证据/判读 owner）承担 Q0-04/05/06。它们是未来操作职责，不是待写业务源码单元。

路径：QC 经 IF-QIN 交付已验证文件→QE 本地库/INI 初始化→IF-QLIB vendor 编译→IF-QLIB DUT 编译→IF-QELAB 合法绑定/优化→QR 经 IF-QLOG 保存证据与终态；任何失败走 QR，后续不执行。没有硬件反馈/背压环路，没有接受 AXI 或 DDR 事务。

| QIN | QC→QE：基线 JSON 的 id/category/path/target/bytes/SHA 字符串与长度非负整数；file31+tool4+context9 身份逐项确认，禁止重名目标/逃出新 work 根。仅31文件复制，9上下文只读；批准范围和 work 已存在检查必须先于复制。审批前快照只证历史，不授权执行；另核live Manifest与实际聊天/登记证据中的指定Q0批准及合法变更，不能把新的审批登记错误归为该历史快照漂移，也不能接受任意live规则变更 |

## D. 局部中文操作草图、存储与清理

1. QC 读回本卡/批准原意和基线，先核44条（含不可变审批前快照）与源码目标去重；另外核真实live Manifest/聊天/批准登记是否支持本次v1/Q0/基线/本地审计，核其自冻结以来合法审批增量，不由快照推定授权。检查新 work 根不存在（若已存在则停止，不覆盖/清空），解析既有 Work 链接的绝对路径仍在批准根。失败记录 NOT_RUN，不创建工作副本。
2. 通过后仅建新 work/report 根，逐31条复制原字节，保持 input/rtl 层级和 input/vendor 目标；复制后逐条再核 SHA。保留 I01 的原身份另记在元数据。本地 INI 是获批后允许的派生配置，后续映射变化单独记录，不能仍称与 I01 逐字节相同。
3. QE 仅用四个冻结工具入口：依次创建 `work`、`efinix` 库并设置本地映射；厂商文件按 V01–V15 顺序用 `vlog` 的 `-work efinix -sv` 模式编译。实际调用的参数作为逐项 argv 存元数据，不生成 .do/.ps1 runner；所有命令在新 work 根调用，使用既有 ASCII 路径。
4. vendor 阶段成功后，按 D01–D14 顺序以 `vlog -work work -sv` 模式编译，include 目录仅本地 input/rtl 与 input/rtl/ddr3_controller；D15 不单独编译。没有新增 define、parameter override 或 I2C include。默认参数由原 top 和参数头形成，不从新工具 generic DDR 向导替换。
5. DUT 阶段成功后，用 `vopt` 对 `work.ddr3_top` 做合法展开/优化，选择 `+acc`、`-L efinix` 和输出 `ddr3_q0_opt`。不调用 vsim、不 run0、不加载新波形脚本、不初始化/驱动任何端口。工具内置解析/优化不是 DDR 时钟仿真；展开不能证明运行时 readmem 或初始化成功。
6. 每阶段调用前固定旧阶段成功状态和输出路径；完成后提交退出/日志身份，再决定下一阶段。每个工具进程墙钟上限600秒，等待期间每≤30秒检查进程/新输出并向用户更新；超时只终止本次记录的进程及确认属于它的子进程，保留半成品，不能杀全局同名工具。超时记录 ABORT_TIMEOUT，不据超时判断 DDR 有功能错误。
7. 第一个失败后 QR 保留对应原日志和所有此前产物；剩余阶段写 NOT_RUN_DEPENDENCY。key/隐藏模块/初始化路径未解析时直接报告实际诊断，下一次变更输入须新版本/基线/批准；不当场重生成 IP、加 stub、补同名 RAM 或换模型。没有失败后的自动 retry。
8. QR 写 RUN_REPORT.md/result.json 和产物清单；完整复查44项冻结来源/工具/上下文及受保护既有状态。live Manifest另核本次指定批准和其他有原始授权的合法登记增量，记录前后SHA与归因，不能仍要求它等于审批前快照；正式状态/硬件不随审批新增改变。审计仅按本次明确批准追加本地 JSONL，不落正式 DB；失败也登记。工作副本保留以便复核，不递归删除；回滚是停止使用本 attempt、保留证据，新 attempt 另批准。

状态是操作记录 `PENDING→IDENTITY_OK→LIB_READY→VENDOR_OK→DUT_OK→ELAB_OK→TERMINAL`，不是 RTL 状态机；失败从当前状态直接 TERMINAL，不倒回重用旧成功记录。上一步的“已成功”只表示该步骤实际退出/诊断满足条件，不能在同一个记录中预先提交未来成功。
