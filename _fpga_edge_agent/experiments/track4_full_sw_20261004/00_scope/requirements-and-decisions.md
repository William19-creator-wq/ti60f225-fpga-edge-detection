# 00 需求、目的与有效决策

任务 TRACK4-FULL-SW-001；v0.1；2026-10-04。来源是现有赛题四需求矩阵与本任务聊天。本文件不改变官方条款或项目长期规则。

## 1. 为什么做、当前做到哪里

硬件尚未到货，用户希望验证 Agent 能否按现行 v0.2 的设计前置与代码可理解性要求，完成五项基础、六项高阶的完整软件工程过程：文档先行、分批评审、完整实现、仿真、综合、布局布线、合理引脚和时序、比特流交付。硬件下载之后的步骤暂不执行。

本轮目标进一步明确为：创建结构化文档目录，完成先于整体草图的工作，并完成整体设计布局草图。本轮不扩大为业务实现，也不因硬件未到而删除功能。

已有材料包含 V4 SC431HAI→DDR→Debayer→HDMI 参考工程和安装工具，已有最小 LED 构建及普通 RTL 仿真证据；它们不是本次 11 项功能的实现或验收。本轮新建的内容是设计文档，不是已实现软件。

| UC-07 场景与资源 | Agent权衡性能、片上资源、DDR和时序后提出合理识别范围，展示优化依据 | 用户最新纠正优先；不是提前认定任何一组建议边界已批准 |

| UC-10 隔离 | 隔离软件工程实验，正式H/A/R状态、DB和硬件节点不借本实验判通过 | 前序选项；文档不是SQLite或新正式数据库 |

**撤回的硬边界**：圆直径/矩形短边96–768、长宽比≤3、最多4目标、20%轮廓遮挡、完整入画、对比≥64/255、纹理±16、噪声σ0–8、椒盐≤0.5%。这些只可作为开发评估点，不能恢复为已确认范围。用户并未要求取消资源容量与可辨识性分析；最终边界需有对比证据、独立测试集与设计评审。

## 4. 派生整机要求

| REQ | 规则及原因 |
|---|---|
| DER-01 身份 | 一次结果绑定源frame_id、配置config_id和复位epoch；RGB、边缘、标注来自同一事务，避免重影 |
| DER-02 完整性 | 源帧及结果只有全部必需DDR事务完成且响应正常后才能发布；最后命令发出不等于写入完成 |
| DER-03 所有权 | 采集只能写独占空槽；处理中/冻结/显示/待发布的源帧不得覆盖 |
| DER-04 边界更新 | 控制输入先成为待用配置，再在SOF或帧任务开始锁定快照；在途结果不受新参数污染 |
| DER-05 有限资源 | 结果写槽在任务领取前预留；等待VSYNC时不占用DDR事务锁，不阻断采集/显示 |
| DER-06 错误分类 | 采集损坏、采集容量不足、算法调度跳帧、识别无目标、识别容量溢出分别报告 |
| DER-07 复位 | 跨域安全释放，旧epoch在途写/结果作废；DDR未就绪时拒绝新任务并显示明确状态 |
| DER-08 优化证据 | 同等输入/数值契约比较有效fps、最坏延迟、DDR流量/等待、RAM实际映射、时序余量；不以占满率代替收益 |
| DER-09 可追踪 | 需求—模块—接口/草图—计划代码—测试—真实证据可双向定位；未实现/未运行保持该状态 |

## 5. 成功、失败、未完成如何区分

本轮成功：新目录存在、入口和顺序可读，真实基线/缺口可追踪，11项要求都有模块，整体数据/控制/配置/错误路径和中文操作草图完成，接口与资源风险有说明，文档已读回和检查。

完整软件实验成功需另有实际代码、匹配模型的仿真、数值/整机回归、95%质量报告、综合/PNR/STA及比特流。不能从本轮文档成功推导上述成功。受保护IP不兼容、校准失败、资源/带宽不足、时序违规或识别指标失败都保留失败/待解决记录。
