一、公司介绍 
易灵思（Efinix）是一家专注于可编程逻辑器件的半导体公司，致力于为边缘计
算、机器视觉、工业控制、消费电子等领域提供高性能、低功耗、小尺寸的 FPGA 芯
片与配套开发工具。其 Titanium™ 系列 FPGA 采用先进工艺制程，集成高速 MIPI 
D-PHY 硬核、丰富的 DSP 与片上存储资源，并支持 Sapphire™ RISC-V 软核 SoC，
可实现高效的软硬件协同设计。 
本次竞赛指定平台基于易灵思 Titanium 系列 Ti60F225 FPGA 芯片，搭配 
Efinity® 集成开发环境，参赛队伍可完成从图像采集、硬件加速处理到高清显示输出
的完整嵌入式视觉系统设计，充分锻炼数字逻辑设计、异构计算与系统集成的综合能
力。

三、选题方向 
【赛题一】AI 赋能的「实时绘画」——风格化视频渲染系统 
【赛题背景】 
随着边缘计算与 AI 生成内容（AIGC）技术的发展，实时视频风格化已成为计算
机视觉领域的热点应用。然而，传统方案依赖云端 GPU 或高端 AI 芯片，难以在低
功耗、低成本边缘设备上实现低延迟、高吞吐量的视频流处理。 
本赛题要求参赛队伍基于 RISC-V + FPGA 异构平台，设计一个轻量化神经网络
硬件加速器。利用 FPGA 的并行流水线架构，将风格迁移网络（如简化版 
CycleGAN、Fast Neural Style 或轻量化 CNN）完全或部分硬件化，实现对实时视频流
的逐帧风格化处理。RISC-V 仅负责摄像头采集配置、视频流格式转换、UI 叠加等高
层控制逻辑，从而构建一个低延迟、低功耗、高帧率的边缘 AI 视频处理系统。

【高阶挑战】 
本部分考察对神经网络优化、多风格切换、高吞吐量流水线设计的深度理解。 
1. 多风格实时切换 
• 在 FPGA 内预置至少 2 种不同风格的网络权重（如梵高风格、浮世
绘风格、水墨风格） 。 
• RISC-V 端可通过按键或串口指令，在不重启系统、不重新配置 
FPGA 的前提下动态切换当前风格。 
• 风格切换延迟应低于 100ms，且切换过程不丢帧。 
2. 分辨率与帧率提升 
• 将处理分辨率提升至 1280×720 @ 30fps 或更高。 
• 需对硬件加速器进行流水线深度优化（如层间融合、行流式处理） ，减
少对 DDR 的中间结果读写次数。 
• 鼓励使用 DSP 块 实现高效的卷积计算（如脉动阵列、权重固定
流） 。 
3. 超轻量化网络自设计 
• 鼓励队伍自行设计或剪枝一个网络参数量小于 500KB 的超轻量化风
格迁移网络。 
• 需提交网络结构图、参数量统计表，并与标准网络（如简化版 
CycleGAN）进行画质（PSNR/SSIM）与推理延迟的对比分析。

【给参赛者的技术提示】 
1. MIPI 内置 IP 优先：使用易灵思芯片内置的 MIPI D-PHY RX IP 和 
CSI-2 RX Controller 进行 CSI-2 采集，可大幅降低外部电路复杂度。 
2. 网络轻量化策略：建议优先考虑 U-Net 极小版、Fast Neural Style 的 
1/4 通道版本，或直接使用 二值/三值神经网络（BNN/TNN） 简化乘法器需
求。 
3. 流水线设计关键：避免“整帧输入→整帧输出”的宏流水线，应采用行
流水线（Line-based Pipeline） ，一行图像数据经卷积、归一化、激活后直接输
出，极大减少 DDR 访问次数。 
4. 画质与速度的平衡：不必追求与云端大模型完全一致的画质，体现“边
缘实时性”比“极致画质”更重要。端侧 AI 的产业应用更关注流畅度与低延迟。 
5. 展示效果最大化：建议对着彩色图案、人脸或风景画进行展示，风格
化前后对比会更明显。若能做到挥手切换风格，现场互动效果极佳。 
【赛题二】基于 RISC-V 与 FPGA 异构架构的 2D 图形渲染加速引擎 
【赛题背景】 
在早期的 2D 游戏机和现代嵌入式 GUI 系统中，如果完全依靠 CPU 通过死循
环逐个像素搬运来实现图像的渲染，会极大占用 CPU 资源并导致帧率（FPS）骤降。
现代计算架构的核心趋势是“异构计算与软硬件协同设计（HW/SW Co-design）”。 
本赛题要求参赛队伍基于 RISC-V + FPGA 异构平台，设计一个定制的硬件 2D 
渲染加速器。将 RISC-V 从繁重的像素搬运工作中解放出来，RISC-V 仅负责高层逻
辑与下发指令，由 FPGA 硬件端完成底层像素的高速搬运与混合。

【任务说明】 
参赛队伍需在 RISC-V 端运行游戏或图形界面逻辑，并在 FPGA 端设计一个通过
标准总线（如 AXI4 / Wishbone）挂载的 2D 硬件加速引擎（BitBlt Engine） 。系统需
能够将内存（DDR/SDRAM）中的图像数据高效搬运至显存（Framebuffer） ，并最终通
过 VGA/HDMI 接口输出至显示器。 
【基础要求】 
本部分考察学生对总线协议、视频时序以及软硬接口的基础掌握能力。 
1. 硬件 2D 位块传输（BitBlt）引擎设计： 
o FPGA 端需实现解析 RISC-V 发送的渲染指令（指令需包含：操
作类型、源地址、目的地址、宽度、高度） 。 
o 硬件支持基础的“图像块拷贝（Block Copy）”和“纯色填充（Solid 
Fill）”。 
o 生成标准 VGA/HDMI 时序，将显存内容输出至显示器（最低分
辨率要求 640×480 @ 60Hz）。 
2. 总线读写与存储器优化： 
o 加速器必须通过系统总线直接访问内存。要求合理使用突发传输
（Burst Transfer）和内部 FIFO 缓存，以提高内存带宽利用率。 
3. 软件驱动与基础 Demo： 
o RISC-V 端需编写 C 语言驱动程序配置寄存器，并实现双缓冲机
制（Double Buffering）以避免画面撕裂（Tearing）。 
o 提供一个基础测试 Demo（例如：大量方块的随机移动、多张大图
的快速切换） ，并能在屏幕上实时对比显示“纯软件 CPU 渲染”与“硬件加
速渲染”的帧率差异。

【关键技术模块说明】 
1. 行缓存（Line Buffer）设计 
• Sobel 算子需要同时访问 3 行数据的同一列，因此需缓存 2 行数据 
• 实现方式：用 2 个 FIFO 或 Block RAM，每行深度为图像宽度（如 
640） 
• 当前行数据 + 缓存行 1 + 缓存行 2，配合列计数器，生成 3×3 窗口 
• 时序控制：每来一个像素，行缓存和窗口寄存器同步更新 
2. Sobel 计算流水线设计 
基础版计算流程： 
第一级：计算 Gx 和 Gy 的部分和（窗口数据读取） 
第二级：完成 Gx 和 Gy 的完整计算 
第三级：计算梯度幅值 G = |Gx| + |Gy| 
第四级：阈值比较，输出二值边缘 
优化版可采用四级流水线，最高频率可达 220MHz。 
3. 中值滤波排序网络（高阶挑战） 
• 输入 9 个 8 位数据，输出中位数 
• 排序策略：先对 3 行各自排序（各 3 个数据） ，再对列排序 
• 典型实现：9 个数据 → 比较器网络 → 5 个时钟周期内输出中值 
4. 全流水线处理 
• 摄像头输出一个像素 → 灰度化 → （中值滤波） → Sobel → 显示输
出 
• 每个模块间用寄存器打拍，无反馈环路，保证每个时钟输出一个结果 
• 理论上可实现“零延迟”实时处理

【给参赛者的技术提示】 
1. 分模块调试策略 
建议按以下顺序逐步调试，每步验证通过再进入下一步： 
• ① HDMI/VGA 显示彩条（验证显示通路） 
• ② 摄像头采集并直通显示（验证采集通路） 
• ③ 加入灰度转换模块 
• ④ 加入 Sobel 边缘检测模块 
• ⑤ 逐步添加高阶挑战功能 
这种模块化调试方法能大幅降低调试难度，避免“最后一刻才发现问题”。 
2. Line Buffer 是核心难点 
Sobel 需要 3×3 窗口，这意味着必须缓存 2 行数据。理解“滑动窗口”机制是关
键： 
• 用两个行缓存（Line Buffer）分别存储前一行和前两行数据 
• 每来一个新像素，更新窗口寄存器的三行三列 
• 建议先用仿真工具观察行缓存输出波形，确认窗口数据正确后再上板 
参考网上的 Verilog 实现方案，基础版使用两个 line_buffer 即可构建 3×3 窗
口。 
3. 注意时序约束 
• 摄像头像素时钟（如 25MHz @ 640×480）和 VGA 像素时钟
（25MHz）可以同频，简化设计 
• 如果不同频，需要异步 FIFO 做跨时钟域处理 
• 优化版 Sobel 采用四级流水线，可将最大频率提升至 220MHz 
4. 资源优化技巧 
• 使用移位加法代替乘法：×2 可用{data, 1'b0}实现，×3 可用{data, 1'b0} 
+ data 实现 
• 梯度幅值用|Gx|+|Gy|代替 sqrt(Gx²+Gy²)，节省 DSP 资源且效果足够 
• 阈值处理可滤除噪声，输出更干净的边缘

• 结合实际应用需求完成小型化、低功耗或高可靠性设计。

方面的优势。
