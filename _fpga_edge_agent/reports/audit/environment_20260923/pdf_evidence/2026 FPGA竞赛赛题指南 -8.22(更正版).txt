赛题一：AI赋能的「实时绘画」
===== PDF PAGE 11 =====
赛题背景与任务
Real-time AI Video Stylization
实时视频风格化
随着边缘计算与 AI 生成内容（AIGC）技术的发展，实时视频风格化已成为计算机视觉领域的热点应用。然而，传统方案依赖云端 GPU 或
高端 AI 芯片，难以在低功耗、低成本边缘设备上实现低延迟、高吞吐量的视频流处理。
本赛题的设立初衷，正是为了探索如何突破传统方案的性能瓶颈，在 低功耗边缘计算设备 上实现兼具高画质与高吞吐量的视频流处理能力
。
本赛题要求基于 RISC-V + FPGA 异构平台，设计一个轻量化神经网络硬件加速器。利用 FPGA 的并行流水线架构，将风格迁移网络（如
简化版 CycleGAN 、Fast Neural Style 或轻量化 CNN）完全或部分硬件化，实现对实时视频流的逐帧风格化处理。 RISC-V 仅负责摄像头
采集配置、视频流格式转换、 UI 叠加等高层控制逻辑，从而构建一个低延迟、低功耗、高帧率的边缘 AI 视频处理系统
核心任务要求：参赛队伍需设计并实现一个完整的实时视频风格化系统。 (1)系统通过 MIPI CSI-2 采集摄像头视频流，(2)在 FPGA 中完成
轻量化风格迁移网络的推理加速，将每一帧图像转换为指定艺术风格（如梵高、浮世绘、水墨画等）， (4)最终通过 HDMI 输出处理后的视
频流。(5)RISC-V 端需实现 UI 叠加功能，(6)可同时显示原画与风格画对比视图。
===== PDF PAGE 12 =====
核心任务拆解——基础要求
1. MIPI 视频流采集与预处理
• 利用 Ti60 FPGA 的 MIPI 高速 I/O 资源，结合 MIPI D-PHY RX IP 和 CSI-2 RX Controller，完成 CSI-2 摄像头接入。（SC431HAI）。
• FPGA 端需实现 MIPI CSI-2 协议解析、RAW 转 RGB（如 debayer 算法）、图像缩放（Resize）至目标分辨率（最低要求：640×480 @ 30fps）。
• 实现双缓冲（Ping-Pong Buffer）机制，将预处理后的帧存入外部 DDR 存储器，确保数据流不丢帧。
2. 轻量化风格迁移网络的硬件加速器设计
• 选择一个轻量化风格迁移网络（参考：简化版 CycleGAN、Fast Neural Style、或自行设计的微型 CNN）。
• FPGA 端需为该网络设计一个硬件加速器，至少实现：
✓ 卷积层（Convolution）硬件化，支持 3×3 或 5×5 卷积核。
✓ 激活函数（如 ReLU）硬件化。
✓ 批归一化（Batch Normalization）或实例归一化（Instance Normalization）的硬件近似计算。
• 加速器需通过系统总线（如 AXI4）从 DDR 读取输入图像块，经流水线处理后写回结果帧。
3. HDMI 视频输出与软硬件协同
• 生成标准 HDMI 时序（最低要求 720p @ 60fps 或 1080p @ 30fps），从 DDR 读取风格化结果帧并输出至显示器。
• RISC-V 端完成：
✓ 摄像头初始化与寄存器配置。
✓ 风格迁移网络权重的加载与部署。
✓ 硬件加速器的任务调度（启动、等待完成、中断处理）。
• 实现原画 vs 风格画对比显示：屏幕左侧显示原始摄像头画面，右侧显示风格化后画面（或通过按键切换全屏模式）。
4. 基础 Demo 与性能验证
• 提供一个基础测试 Demo，展示实时风格化效果。
• 在屏幕上叠加显示当前帧率（FPS），要求稳定达到 15fps 以上（640×480 分辨率）。
基础目标：系统完整性

===== PDF PAGE 13 =====
核心任务拆解——高阶挑战
进阶目标：极致优化与创新
鼓励针对硬件特性重构算法、挖掘并行计算潜力，在有限资源下实现更高分辨率、更低延迟，并结合创意交互展现成果
。
本部分为拉开队伍差距的核心考核点，考察对神经网络优化、多风格切换、高吞吐量流水线设计的深度理解
1. 多风格实时切换
• 在 FPGA 内预置至少 2 种不同风格的网络权重（如梵高风格、浮世绘风格、水墨风格）。
• RISC-V 端可通过按键或串口指令，在不重启系统、不重新配置 FPGA 的前提下动态切换当前风格。
• 风格切换延迟应低于 100ms，且切换过程不丢帧。
2. 分辨率与帧率提升
• 将处理分辨率提升至 1280×720 @ 30fps 或更高。
• 需对硬件加速器进行流水线深度优化（如层间融合、行流式处理），减少对 DDR 的中间结果读写次数。
• 鼓励使用 DSP 块 实现高效的卷积计算（如脉动阵列、权重固定流）。
3. 超轻量化网络自设计
• 鼓励队伍自行设计或剪枝一个参数量小于 500KB 的超轻量化风格迁移网络。
• 需提交网络结构图、参数量统计表，并与标准网络（如简化版 CycleGAN）进行画质（PSNR/SSIM）与推理延迟的对比分析。
4. 创意交互展示
• 在基础对比视图之外，增加趣味交互功能。例如：
✓ 语音控制切换风格。
✓ 手势识别（如挥手）触发特殊滤镜效果。
✓ 将风格化画面实时推流至手机 APP（通过 WiFi 模块）。
• 鼓励录制 “抖音/B站风格”展示短视频，作为附加材料提交，增强作品传播性。

赛题二：基于 RISC-V 与 FPGA 异构架构的
2D 图形渲染加速引擎
===== PDF PAGE 15 =====
赛题背景与任务
2D Rendering Acceleration
硬件加速挑战
在早期的 2D 游戏机和现代嵌入式 GUI 系统中，如果完全依靠 CPU 通过死循环逐个像素搬运来实现图像的渲染，会极大占用 CPU 资源并
导致帧率（FPS）骤降。 本次赛题正是针对这一痛点，要求设计一款专用的硬件 2D渲染加速器，以此替代软件渲染的低效模式，显著提升
图形处理的整体效率。 现代计算架构的核心趋势是“异构计算与软硬件协同设计（ HW/SW Co-design）”。
本赛题要求参赛队伍基于 RISC-V + FPGA 异构平台，设计一个定制的硬件 2D 渲染加速器。将 RISC-V 从繁重的像素搬运工作中解放出来，
RISC-V 仅负责高层逻辑与下发指令，由 FPGA 硬件端完成底层像素的高速搬运与混合。
核心任务要求：参赛队伍需在（1） RISC-V 端运行游戏或图形界面逻辑，（ 2）在 FPGA 端设计一个通过标准总线（ AXI4 ）挂载的 2D 硬
件加速引擎（BitBlt Engine），（3）系统需能够将内存（DDR3）中的图像数据高效搬运至显存（ Framebuffer ），（4）然后通过
HDMI 接口输出至显示器。
===== PDF PAGE 16 =====
核心任务拆解——基础要求
1.硬件 2D 位块传输（BitBlt）引擎设计：
• FPGA 端需实现解析 RISC-V 发送的渲染指令（指令需包含：操作类型、源地址、目的地址、宽度、高度）。
• 硬件支持基础的“图像块拷贝（Block Copy）”和“纯色填充（Solid Fill）”。
• 生成HDMI 时序，将显存内容输出至显示器（最低分辨率要求 640x480 @ 60Hz）。
2.总线读写与存储器优化：
• 加速器必须通过总线直接访问内存。使用突发传输（Burst Transfer）和内部 FIFO 缓存，以提高内存带宽利用率。
3.软件驱动与基础 Demo：
• RISC-V 端需编写驱动程序配置寄存器，并实现双缓冲机制（Double Buffering）以避免画面撕裂（Tearing）。
• 提供基础测试 Demo（例如：大量方块的随机移动、多张大图的快速切换），并在屏幕上实时对比显示“纯软件 CPU 渲染”与“硬件
加速渲染”的帧率差异。
基础目标：考察学生对总线协议、视频时序以及软硬接口的基础掌握能力。
===== PDF PAGE 17 =====
核心任务拆解——高阶挑战
进阶目标：要求实现现代 2D 游戏引擎中的高级图层渲染管道。完成度越高，得分越高。
1. 硬件 Alpha 混合 (Hardware Alpha Blending)：
• FPGA 加速器在搬运前景图层（Sprite）时，利用内部 DSP/硬件乘法器，实时读取背景像素并执行透明度混合计算：
输出像素 = 前景像素 * Alpha + 背景像素 * (1 - Alpha)。
2. 颜色键控去背 (Color Keying)：
• 硬件支持设定“透明色”（如纯品红色）。在搬运图像时，自动跳过透明色像素，实现不规则边缘精灵图（Sprite）的完
美渲染。
3. 高负载互动游戏 Demo 演示：
• 在 RISC-V 上运行一个具有极高同屏元素数量的游戏 Demo（如《吸血鬼幸存者》的简化版或类似《东方Project》的
弹幕射击游戏）。
• 在开启硬件加速（Alpha 混合 + Color Keying）的情况下，挑战保持 60 FPS 稳定运行时的同屏活动元素（Sprite）数
量极限。

赛题三：多模态AI智能终端
===== PDF PAGE 19 =====
赛题背景与任务
Real-time Image Edge Detection System
实时图像边缘检测系统
在智慧康养、智能家居与安防监控等关键领域，单一的传感器（如纯视觉摄像头）往往无法提供足够可靠、全面的环境感知。例如，仅用
摄像头做老人跌倒检测，在光线昏暗、遮挡或视角不佳时极易漏报；仅用红外传感器则无法获知行为细节。现实场景需要同时融合视觉图
像、人体温度分布、环境温湿度等多维信息，才能做出“跌倒的是人而非物体”、“体温异常的人需要关注”等准确判断。
传统方案存在明显短板：云端 AI方案延迟高、依赖网络，且涉及隐私的视频上传至云端难以被用户接受；而采用“ ARM MCU + 多个协处
理器”的边缘方案，开发复杂、功耗高、算力分散，难以在低功耗下实现实时多模态融合。
核心任务要求：基于Ti60 FPGA ，构建一个“视觉+红外温度+环境传感”的多模态AI智能终端，在本地完成数据采集、融合推理与事件响
应，真正实现低延迟、高隐私、高可靠的边缘智能终端。
===== PDF PAGE 20 =====
核心任务拆解——基础要求
任务1：多传感器数据采集与FPGA预处理（基础）
目标：建立多模态传感器的数据采集通路，实现数据预处理和时间对齐。
要求：通过MIPI CSI接口驱动摄像头，完成视频流实时采集，分辨率>=720p@30fps
通过I2C接口驱动红外温度传感器（如MLX90640），实现人体温度分布采集
通过I2C接口驱动温湿度传感器（如SHT30），实现环境温度采集
在FPGA内实现数据预处理：滑动平均滤波、异常值剔除、多传感器时间戳对齐
通过HDMI/LCD显示各传感器实时数据（视频画面+温度热力图+环境参数叠加显示）
技术要点提示：
✓ 多传感器时间对齐：以视频帧时间戳为主时间基准，对红外温度和环境传感器数据进行时间戳标记，通过最近时间匹配、缓
存或插值实现多模态数据的时间对齐。
✓ 温度数据预处理：读取 MLX90640 原始红外数据及 EEPROM 校准参数，完成环境温度、增益、偏置、发射率等补偿，计
算各像素目标温度；可采用定点化、分段近似或 LUT 等方法对部分计算进行硬件优化。
✓ 显示叠加：在HDMI画面上分区域显示——主区域视频画面、侧边温度热力图小窗、底部环境参数文字
✓ I2C多设备管理：使用I2C地址区分不同传感器，设计分时复用控制器
===== PDF PAGE 21 =====
核心任务拆解——基础必做
任务2：多模态AI处理与感知决策（核心）
目标：在FPGA端实现轻量级AI推理和多模态融合决策。
要求：
• RISC-V + FPGA AI 推理：在 Ti60 FPGA 内部署 RISC-V 软核，运行 TinyML 等轻量级 AI 推理框架，实现人体检测、姿态识别或其他视觉感知算
法。鼓励利用 FPGA DSP、BRAM、并行逻辑及 RISC-V 自定义指令实现卷积、矩阵运算等关键算子的硬件加速，提高推理性能。运动分析：通
过帧差法或光流法（Farneback简化版），分析人体运动状态（静止/行走/跌倒/异常动作）
• 多模态融合决策：结合视觉检测结果（位置、动作）+ 红外温度数据（体温异常检测）+ 环境数据（温度/湿度异常），进行综合判断
• 事件检测与响应：实现以下场景之一，或自定义一个智能场景：
✓ 跌倒检测：人体姿态突变+长时间静止+温度正常（排除倒地物体），触发报警
✓ 智能空调控制：检测人员位置分布和体温，结合环境温度，输出空调控制建议（或驱动GPIO模拟控制）
✓ 入侵检测：非授权时段人体出现+体温正常（排除热源干扰），触发报警
✓ 本地报警与显示：检测到异常事件时，通过LED闪烁+蜂鸣器报警+HDMI画面红色边框提示+显示事件类型和置信度
技术要点提示：
✓ 轻量级神经网络：建议使用定点量化（INT8），利用DSP做矩阵乘法加速。网络结构建议不超过5层卷积+2层全连接，参数量控制在100K以内
✓ 多模态融合策略：加权投票法——视觉置信度60% + 温度置信度25% + 环境置信度15%，综合得分超过阈值触发事件
✓ 帧差法运动检测：当前帧与背景帧差分，阈值分割后计算连通域面积和质心位移，判断运动类型

赛题四：基于FPGA的实时图像边缘检测系统
===== PDF PAGE 24 =====
赛题背景与任务
Real-time Image Edge Detection System
实时图像边缘检测系统
图像边缘检测是数字图像处理领域最经典、最基础的技术之一，广泛应用于目标识别、工业检测、医学影像分析、自动驾驶等场景。传统
基于软件（CPU）的边缘检测方案受限于串行处理架构，难以满足高分辨率、高帧率的实时性要求；而 FPGA凭借其天然的并行处理能力，
能够以流水线方式逐像素处理图像数据，实现“边采集、边处理、边显示”的实时效果。
本赛题要求参赛者基于易灵思 FPGA开发板，搭建一个完整的实时图像处理系统：通过摄像头采集图像，在 FPGA内部完成灰度化、中值滤
波、Sobel边缘检测等处理，最终通过HDMI/VGA接口将处理结果实时显示在显示器上。题目涵盖了 FPGA开发的核心技能模块 ——外设驱
动（摄像头、显示器）、数据流控制、数字图像处理算法硬件化，是一个综合性强但路径清晰的竞赛题目。
核心任务要求：计一个基于FPGA的实时图像边缘检测系统。系统通过 DVP或MIPI接口接入摄像头，实时采集视频流数据；在 FPGA内部完
成彩色图像转灰度、中值滤波去噪、 Sobel算子边缘检测等处理；最后驱动 HDMI/VGA显示器，将原始图像和处理后的边缘图像分屏或叠
加显示。整个系统要求实现全流水线处理 ——摄像头采集一行的同时，FPGA对该行数据进行处理并输出显示，实现“零延迟”的实时效果。
===== PDF PAGE 25 =====
核心任务拆解——基础要求
1. 摄像头驱动与图像采集
• 分辨率要求：640×480或以上
• 采集图像数据并存入行缓存（FIFO或Block RAM），为后续处理做准备
• 要求图像采集稳定，无丢帧、无错位
2. 彩色图像转灰度处理
• 要求使用FPGA内部的DSP块或移位加法实现乘法运算，避免使用除法器
• 灰度转换是边缘检测的前置步骤
3. Sobel边缘检测算法实现
• 实现3×3 Sobel算子，计算水平方向梯度Gx和垂直方向梯度Gy
• Sobel算子卷积核：
➢ Gx（x方向梯度）：[-1, 0, +1; -2, 0, +2; -1, 0, +1]
➢ Gy（y方向梯度）：[-1, -2, -1; 0, 0, 0; +1, +2, +1]
• 梯度幅值近似计算：G = |Gx| + |Gy|（避免开方运算，节省硬件资源）
• 通过阈值比较输出二值化边缘图像（阈值可参数化配置）
• 需设计行缓存模块（Line Buffer）缓存2行数据，实现3×3窗口的滑动处理
基础目标：本部分考察参赛者对FPGA外设驱动、数据流控制、基础图像处理算法的掌握能力。
4. HDMI显示驱动
• 生成标准HDMI时序（最低要求：640×480@60Hz）
• 实现分屏显示：屏幕左侧/上半部分显示原始灰度图像，右侧/
下半部分显示边缘检测结果
• 或实现画中画叠加显示
• 显示稳定，无闪烁、无撕裂
5. 基础验证
• 提交完整RTL源码（Verilog/VHDL）和约束文件
• 提供演示视频：摄像头对着简单几何图形（如黑白棋盘格、印
有数字的纸张、人脸轮廓），展示边缘检测效果
===== PDF PAGE 26 =====
核心任务拆解——高阶挑战
进阶目标：为有余力的队伍提供拓展空间，完成度越高，得分越高。算法复杂度和视频帧频也是考核维度。
1. 中值滤波去噪
• 在灰度化之后、边缘检测之前插入3×3中值滤波模块
• 实现9个像素值的排序，取中位数作为输出
• 有效抑制椒盐噪声，提升边缘检测质量
• 需合理设计排序网络（可采用并行比较网络，避免串行排序）
2. 实时阈值调节
• 通过板载按键或拨码开关，实时调整Sobel边缘检测的阈值
• 效果：按“+”键提高阈值（边缘减少），按“-”键降低阈值（边缘增多）
• 需设计按键消抖模块与阈值寄存器
• 该功能在现场演示时能直观展示阈值对边缘检测结果的影响
3. 帧缓存与DDR控制
• 将一帧完整图像写入外部DDR存储器，实现“采集-存储-读取-处理”分离
• 可实现回放、帧冻结、多帧对比等功能
4. Canny边缘检测（算法升级）
• 实现更高级的Canny边缘检测算法（高斯滤波→梯度幅值和方向计算→非
极大值抑制→双阈值分类 → 滞后边缘连接）
• Canny相比Sobel能获得更精确、更连续的单像素边缘
• 但实现复杂度显著提升，需要更精细的流水线设计
5. 边缘叠加彩色输出
• 将检测到的边缘以彩色形式（如红色边缘线）叠加到原始彩色图像上输出
• 视觉效果更直观，适合现场展示
• 需要处理RGB三个通道的叠加逻辑
6. 简易目标识别（创意拓展）
• 在边缘检测的基础上，识别画面中的特定形状（如圆形、矩形）
• 可采用特征匹配法：在边缘图像中检测轮廓，计算几何特征
• 将识别结果显示在屏幕上（如“检测到圆形”）
