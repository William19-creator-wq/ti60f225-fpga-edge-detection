Demo10 适配 1024×600 HDMI 显示屏解决方案

作者：LeoXuanyi　|　适用工程：Ti60F225 Demo10（SC431HAI → MIPI CSI → DDR3 → HDMI）　|　日期：2026-10-03
结论：屏幕的物理分辨率是 1024×600，但不能据此直接把 Demo10 的宽高改为 1024×600。应先确认屏幕 HDMI 控制板能够接收的标准模式，然后用 FPGA 内部色条单独验证 HDMI。推荐优先测试标准 1280×720@60Hz；色条正常后，再恢复摄像头、MIPI 和 DDR 链路。

1. 问题本质

Demo10 默认目标是摄像头到 HDMI 的完整视频通路，而不是单纯的 HDMI 测试工程：

SC431HAI
摄像头
I²C 配置
MIPI CSI 接收
像素整理
DDR3
帧缓存
DVI/HDMI
显示输出

其中任意一级没有启动，都可能造成黑屏或“无信号”。小尺寸 HDMI 屏通常由 1024×600 液晶面板加 HDMI 缩放控制板组成。面板分辨率不等于 HDMI 输入分辨率；控制板可能接受 720P、1080P 后缩放，也可能只支持少数模式。

当前工程还有一个明显风险：顶层采用 1920×1080，但同步和消隐参数不是标准 1080P60。普通显示器可能容忍，小型 HDMI 控制板更可能直接拒绝该时序。

2. 第一步：确认屏幕支持的 HDMI 输入模式

  1. 给屏幕单独稳定供电，不要只依赖电脑或开发板 USB 口供电。
  2. 使用同一根 HDMI 线连接 Windows 电脑和屏幕。
  3. 依次测试 1920×1080 @ 60Hz、1280×720 @ 60Hz。
  4. 打开 Windows“设置 → 系统 → 显示 → 高级显示”，记录“桌面模式”和“活动信号模式”。
  5. 如果能够读取 EDID，保存首选时序、像素时钟、前肩、同步宽度、后肩和同步极性。
电脑测试结果FPGA侧处理
1080P60 正常可继续使用 1080P，但必须换成标准 1080P 时序并检查 148.5 MHz 像素时钟。
仅 720P60 正常优先输出标准 720P；摄像头也应配置为 1280×720，或增加裁剪/缩放模块。
仅 1024×600 正常必须依据 EDID 或厂家时序表配置，不能猜像素时钟与消隐参数。
电脑也无显示先排查显示屏供电、HDMI线和屏幕控制板，不要修改 FPGA。

3. 推荐方案：先制作标准 720P 色条诊断位流

这一步绕开摄像头、I²C、MIPI 和 DDR，只验证 FPGA 到 HDMI 显示屏的通路。涉及文件：

  • rtl/color_bar.v
  • rtl/ti60f225_oob_top.v
  • ti60f225_oob.peri.xml 对应的 Efinity Interface Designer PLL 配置

3.1 切换色条分辨率

打开 rtl/color_bar.v，把当前定义：

`define VIDEO_1920_1080

修改为：

// `define VIDEO_1920_1080
`define VIDEO_1280_720

该文件已经包含标准 720P60 参数：

H_ACTIVE = 1280;
H_FP     = 110;
H_SYNC   = 40;
H_BP     = 220;

V_ACTIVE = 720;
V_FP     = 5;
V_SYNC   = 5;
V_BP     = 20;

3.2 解除 HDMI 对 DSI 初始化的依赖

打开 rtl/ti60f225_oob_top.v，找到：

assign vid_rst_n = dly_cnt[26];

诊断阶段暂时改成：

// HDMI-only diagnostic: release video reset after all PLLs lock
assign vid_rst_n = w_arstn;

原因是原逻辑只有在 w_confdone 有效后才释放 HDMI，而 w_confdone 来自工程中残留的 MIPI DSI 面板初始化链。它不应该成为 HDMI 色条测试的必要条件。

3.3 启用色条模块

在顶层约 942 行附近取消 color_bar 实例的注释：

color_bar color_bar_m0 (
    .clk   (hdmi_tx_slow_clk),
    .rst   (~vid_rst_n),
    .hs    (video_hs),
    .vs    (video_vs),
    .de    (video_de),
    .rgb_r (video_r),
    .rgb_g (video_g),
    .rgb_b (video_b)
);

3.4 将 DVI 编码器切换到色条输入

在 dvi_encoder 实例中临时使用以下连接：

.i_bdata (video_b),
.i_gdata (video_g),
.i_rdata (video_r),
.i_hs    (video_hs),
.i_vs    (video_vs),
.i_de    (video_de),

不要继续沿用原代码里 R/B 和 HS/VS 互换的连接进行第一次标准色条验证。

3.5 重新配置 USER_PLL

仅修改分辨率宏不够。原 1080P 时钟会使 720P 色条以错误刷新率输出。打开 Efinity Interface Designer 中的 USER_PLL，根据 25 MHz 板载输入时钟重新计算并生成：

时钟720P60目标值用途
hdmi_tx_slow_clk74.25 MHzHDMI像素时钟、DVI编码器
hdmi_tx_fast_clk371.25 MHzTMDS 5倍高速时钟
vid_clk_dvi237.125 MHz双像素帧缓存时钟；纯色条阶段可暂不参与数据路径

保持高速/低速时钟比为 5:1。应通过 Efinity PLL 配置界面生成参数，不要手工猜测 PLL 分频值。

3.6 编译与烧录

  1. 运行 Synthesis、Place、Route、Generate Bitstream。
  2. 确认没有未约束 HDMI 时钟、PLL 未锁定或 TMDS 引脚错误。
  3. 在 Programmer 中使用 JTAG 烧录新生成的 outflow/ti60f225_oob.bit。
  4. 观察显示器是否识别到 1280×720@60Hz，并显示八色条。

4. 色条测试结果如何处理

现象结论下一步
720P 色条正常屏幕、HDMI线、TMDS引脚和HDMI时钟基本正常。恢复帧缓存，再逐级恢复DDR、MIPI和摄像头。
显示器仍提示“无信号”问题在摄像头之前，优先检查 PLL、复位、TMDS引脚、同步极性和位流是否来自当前工程。使用示波器检查 HDMI 时钟差分输出，并核对引脚约束。
显示器识别720P但黑屏时钟与同步可能存在，色条数据或DVI编码输入连接有误。检查 video_de、RGB及DVI编码器连接。
画面滚动、错位或闪烁像素时钟、总行场周期或同步极性不正确。复核 1650×750 总时序及74.25 MHz像素时钟。

5. 色条正常后恢复摄像头链路

5.1 先恢复 DDR 帧缓存

建议临时把 LED 改为可观察的状态：

// 删除原来的 assign led[0] 后再加入
assign led[0] = cal_done;       // DDR校准完成
assign led[1] = w_arstn;        // 全部PLL锁定
assign led[2] = w_confdone;     // 原DSI初始化完成，仅用于观察
assign led[3] = w_mipi_rx_de;   // MIPI像素数据活动

D0、D1 由高电平点亮。当前原始工程只有 led[0] 被驱动，led[1..3] 未驱动，因此原始 D1 常亮没有诊断意义。

5.2 恢复缺失的摄像头 I²C 源文件

项目 XML 列出了以下模块，但当前 rtl/cam_i2c_ctrl 目录内只有文档，缺少对应 Verilog：

rtl/cam_i2c_ctrl/i2c_master/i2c_master_byte_ctrl.v
rtl/cam_i2c_ctrl/i2c_master/i2c_master_top.v
rtl/cam_i2c_ctrl/i2c_master/i2c_master_bit_ctrl.v
rtl/cam_i2c_ctrl/i2c_master/oc_i2c_master.v
rtl/cam_i2c_ctrl/i2c/i2c_16addr_8data.v
rtl/cam_i2c_ctrl/i2c/i2c_master_reg_rom.v
rtl/cam_i2c_ctrl/i2c/i2c_master_reg_set.v
rtl/cam_i2c_ctrl/i2c/i2c_master_ctrl_top.v

必须从厂家完整 Demo10 包或同版本官方参考工程恢复这些文件，并确认寄存器表确实适用于 SC431HAI。不能用 IMX219/IMX185 的寄存器表直接替换。

5.3 让输入分辨率与输出分辨率一致

如果最终使用 720P HDMI，推荐让摄像头直接输出 1280×720。仅把 HDMI 改为 720P，而摄像头仍输出 1920×1080，当前工程没有明确的视频缩放器，帧缓存尺寸和读写节奏会不一致。

可选路线：

  • 路线A（推荐）：使用厂家提供的 SC431HAI 1280×720@60 初始化寄存器，并把帧缓存参数统一为 1280×720。
  • 路线B：屏幕确认支持标准1080P后，摄像头和帧缓存继续使用1920×1080，只修正标准1080P时序与复位。
  • 路线C：加入1920×1080到1024×600或1280×720的视频缩放模块，资源和带宽开销最大。

6. 如果必须输出原生 1024×600

不能只把 MAX_HRES 和 MAX_VRES 改成 1024、600。1024×600 没有唯一通用的 HDMI 时序，必须取得屏幕控制板 EDID 或厂家时序表。

至少需要以下数据：

  • 像素时钟频率；
  • 水平有效像素、前肩、同步宽度、后肩；
  • 垂直有效行数、前肩、同步宽度、后肩；
  • HSYNC/VSYNC 极性；
  • 刷新率；
  • HDMI控制板是否接受DVI模式以及是否需要音频/InfoFrame。

得到参数后，需要同步修改：

  1. rtl/color_bar.v：新增 1024×600 时序宏；
  2. rtl/ti60f225_oob_top.v：分辨率和帧缓存时序；
  3. USER_PLL：像素时钟、5倍TMDS时钟和双像素时钟；
  4. 摄像头输出配置或图像缩放模块；
  5. DDR帧地址跨度、每行字节数和帧尺寸参数。

7. 最终推荐实施顺序

  1. 用电脑确认屏幕支持 720P60 或 1080P60。
  2. 保存当前 Git 状态，建立单独修改提交。
  3. 生成标准720P色条位流，绕开摄像头和DDR。
  4. 确认 HDMI 色条稳定显示。
  5. 恢复 DDR 并确认 cal_done。
  6. 恢复完整、型号匹配的 SC431HAI I²C 初始化文件。
  7. 确认 MIPI 时钟、lane 和 w_mipi_rx_de。
  8. 把摄像头、帧缓存和HDMI输出统一为同一分辨率。
  9. 最后再恢复音频、DSI残留逻辑或其他附加功能。
最短可行路径：先用标准 720P 色条证明 HDMI 能显示；如果成功，再让 SC431HAI 输出 1280×720 并恢复 DDR 帧缓存。这比直接猜测 1024×600 时序成功率高，也最容易定位故障。
本文档基于当前工作区 Demo10 源码分析生成。修改前后均应使用 Git 记录差异，不采用复制整个工程目录的方式备份。
