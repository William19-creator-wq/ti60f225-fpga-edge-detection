# 人工RAW和直接RGB色卡对照

用户提供的 COLORCARD 照片显示：顶部白黄青绿紫红蓝黑顺序正确，白色和灰阶无相机区那种明显紫偏；下方相机区仍紫。照片不是色度仪测量，只支持优先调查编码器之前的路径，不能证明全部HDMI参数无误。

沿用用户自主修改、测试、操作Programmer的授权及本批本地审计例外；不再请求设计审批或写操作草图。独立副本 track4_v7_rawcard_001_20261017 基于已登记 COLORCARD 的143份输入，新模块使输入总数144。原始资料、旧bit和数据库不变。

保留顶部直接HDMI彩条和灰阶。新增rawcard_overlay在ch0 RAW之后、现有debayer之前插入人工GBRG数据：224..319输入行八色，320..415行灰阶，其余区域保留真实相机；相同行列时序、两像素宽度、零新增拍延迟。P00加原HDMI旁路交换对应人工GBRG，是既有独立坐标模型的约定，并非宣称传感器实际CFA已确定。

人工八色依次为白黄青绿紫红蓝黑，对应高值192、低值32；比顶部全幅彩条暗且饱和度低属于预期。灰阶0..255共16级。行缓存中心为前一行，所以合成区域上下边界和色块边缘可能有一两行/列插值混色；只判读块内部。人工色卡位置约在屏幕上半部中间，最下面仍是相机画面。

验证：tb_rawcard使用XML实际注册的rtl/true_dual_port_ram.v、真实gain/line_buffer/raw_to_rgb/debayer_top，模拟两帧、825600个RAW字；直接检查注入值及非注入区逐位不变，再用独立均匀色块期望检查632448个内部RGB像素（含现有HDMI旁路R/B解释），结果PASS。未以局部仿真声称验证保护编码器、CSI、DDR或快慢像素时钟。上板色卡对照补充快慢像素输出路径证据。

Questa有6条缺少输出端口连接提示：现有line_buffer.o_x的两条，以及测试只消费rgb_datax2而不使用rgb_rout/gout/bout的四条；均为未使用输出，没有输入悬空。编译0错误0警告，仿真0错误。onerror的命令上下文提示不影响PASS与进程返回码。

另核对既有Bayer仿真使用的rtl/debayer/true_dual_port_ram.v与XML实际使用rtl/true_dual_port_ram.v：字节哈希不同，git逐行比较无内容差异（换行格式不同），未发现不同RAM行为；本次直接使用XML版本消除选择歧义。

后续判读：人工RAW色卡内部也正常，则P00链路在该合成GBRG约定下可正确还原颜色，真实相机相位/增益/白平衡继续调查；人工RAW色卡也偏紫而直接RGB色卡正常，则重点查debayer实现、两像素串行化和实际时序。无论哪种结果，都不能把本实验称为相机颜色已修复。
