# HDMI 直接色卡与实时相机对照

用户反馈：HDMI RGB 固定版上板后，画面实时变化，但白色仍偏紫。记录在上一节点 hardware-observation-purple.json。不能把这项结果称为颜色修复通过，也不能由它推断 HDMI 整条路径已正确。

本实验依据用户“无需我的批准，也不用再写草图，按照你的见解写代码测试”及“你来操作电脑进行下载和烧录”的授权继续；沿用本批本地审计例外。原始参考工程、既有比特流、数据库和正式状态不修改。

独立工程 track4_v7_colorcard_001_20261017 基于已登记 RGB/P00 的 142 文件逐项 SHA256 核对复制。只新增 colorcard_overlay.v、在 XML 登记该模块、在顶层接入 RGB 数据。摄像头配置、RAW、Bayer、DDR、时钟、管脚及同步保持原样。

屏幕前96行显示白、黄、青、绿、紫、红、蓝、黑，宽度每色240像素；随后96行显示16级灰阶，每级120像素、RGB同为0、17…255；其余行保持此前相机RGB。色卡在148.5MHz单像素域直接替代编码器输入，不经过RAW、DDR、去马赛克、增益和gamma，不增加同步延迟。相机区域保留原有R/B旁路路由，避免混入通道修复。

组合输出由当前x/y选择；x仅在DE中计数，消隐清零；y在DE下降后的采样沿加一，VS上升沿归零。适用1920宽连续有效行。色卡并不验证HDMI保护IP内部，只提供可在实物上辨别的已知输入。

检查对应：tb_colorcard 对两帧806400像素验证颜色、灰阶和随机相机RGB逐位保留，变长消隐、换帧、复位重启；check_build核对143项冻结源码、仅三文件变化、18个setup/hold时钟关系、非负裕量、IO不变、资源和新增警告。硬件待结果反馈后单独登记。

判读：若色卡中性灰/白和三原色正常，而相机仍偏色，下一步优先RAW相位、白平衡及相机RGB计算；若色卡也错色，先追踪编码器/物理输出/显示解释。不能仅因黑白正常排除红蓝交换，必须看彩色顺序。不能仅凭一次正确色卡宣称整个相机链路通过。

当前这版保留P00并不意味着已选定P00正确。P01/P11的偏绿也可能包含正确相位下的白平衡问题，四个候选无一完全正常不能排除相位与白平衡同时有问题。
