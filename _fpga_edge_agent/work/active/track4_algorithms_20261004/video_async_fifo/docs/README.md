# 视频双时钟缓冲：完整记录、有限容量、可见丢失

2026-10-09。TRACK4-VIDEO-ASYNC-FIFO-001 v1，沿自主执行授权及本地审计例外。7份业务/验证输入，原HDK、数据库和硬件未改。先阅读控制面同名设计卡，再看本说明、RTL、独立参考、TB和runs。

## 整体与接口

生产者不能停顿，因此每个 `wr_valid` 写沿是一次新记录尝试。`wr_accept` 表示该次已保存；未接纳立刻形成粘滞丢失，后续写不再进入旧队列。读者使用 `rd_valid/ready`，已接纳记录按序且逐位保持；公开记录在停顿和故障通知到达期间均保持。独立 `rd_fault` 两级同步故障，不靠满数据FIFO运送故障消息。

输入WIDTH位完全不透明，不预设CSI位序或截短帧身份。默认WIDTH128、DEPTH1024，分别支持1…320位、16…4096的2次幂。物理RAM容量DEPTH，另有读域2条前取记录。多位数据经双时钟RAM传输；跨域仅同步寄存后的Gray指针和粘滞故障。写域32位饱和丢失计数不能被读域直接当一致快照。

## 局部语句与交接

写域的 `wbin/wgray` 只在 `wr_accept` 推进。满判定使用当前wgray和同步rgray最高两位反相，旧记录未获取时不能覆盖。同一沿先用旧地址写RAM，再非阻塞提交新指针。`wr_valid&&!wr_ready` 只在运行中记丢失，不改数据指针。

读域 `rbin/rgray` 表示已经从物理RAM获取的进度，释放地址经过写域2FF才可被复用。两个WIDTH位FF槽以head/tail管理；count表示完成记录，pending表示上一沿发RE尚待保存的回复。先计算 `count+pending-pop`，有空信用且不empty才发RE。下一沿将对应bank的实际RDATA放入tail，再翻转tail；消费首槽才翻转head。回复、消费和新RE可同沿进行，因此有数据及ready时可一拍一条。

每512条为一个bank，每20位为一个stripe，原生 `EFX_RAM10` 使用两个真实时钟、同步读、OUTREG0、READ_UNKNOWN；同址并发读写由保守指针/信用禁止。最后条带补零，交付只取原WIDTH位。默认7条带×2bank=14 RAM，另有2×128位槽。没有把RAM内容复位或把失效内存内容当新数据。

共同 `cold_reset_n` 异步断言，每域两级同步释放。停钟域不会假装完成释放/故障同步。禁止单端清FIFO；运行恢复只有外层证明旧借用安全后才能共同冷复位。此组件不输出帧成功或接收closure，FIFO空也不证明CSI末错误已经全部上报。

## 当前源码的实际证据

9个002运行共49个场景，独立参考按外部写接受/读交付核对659248条记录，104次预设的丢失全部计数一致。宽度1/20/21/110/128/192/320，深度16/512/1024/2048/4096，包含三个非整数/不同速率的时钟组合、停钟/恢复、冷复位后新epoch、绕回、held记录与满FIFO独立故障。每个运行先验证fatal出口非零，再核对当前源SHA。

`fifo_hd_002`：写钟约70MHz、读钟100MHz，连续518400条（1080p四像素分组的记录数量）全部接纳和逐位交付，零丢失；不是宣称真实CSI已经输出这些像素。其余运行：fifo_default_002、fifo_w1_d16_002、fifo_w20_d512_002、fifo_w21_d1024_002、fifo_w110_d2048_002、fifo_w192_d1024_002、fifo_w320_d4096_002、fifo_fastwriter_002。较快写钟/较慢读钟用有限突发及明确间断测试，未声称任何不平衡持续流都能无损。

`fifo_map_002`：Ti60F225/I3实际综合14 RAM10、387 FF、445 LUT4、31 ADD、0 DSP，没有综合警告。目标时钟为写14.286ns/读10ns；未做板级PNR/STA，未证明物理亚稳态或Gray位偏斜。生产top必须对Gray源寄存器到第一级同步器设置与源周期相容的延迟/偏斜约束，不能把MAP通过当CDC时序通过。

旧 `fifo_map_001` 因Efinity禁止异步RAM的READ_FIRST失败；草图J1先记录后改READ_UNKNOWN。旧001仿真只对应旧源，其中仍运行的320位测试在源变动后被脚本以Source drift拒绝，未登记为当前通过；所有当前参数重新执行002并通过。旧证据原样保留。

## 追踪与操作次序

VFREQ01 → RAM/指针/槽 → VF01/04/05；VFREQ02 → full/overflow/loss_count → VF02/03；VFREQ03 → head保持/独立fault → VF01/02；VFREQ04 → 两域冷复位与2FF → VF03/06。RTL顶部和设计卡编号可双向定位。

先用 `scripts/run_fifo_sim.ps1` 新RunId验证默认及边界/FullHD，再把通过且源摘要一致的运行交给 `scripts/run_fifo_map.ps1`，读取资源和警告后登记。工程文件可在Efinity打开；该内部端口组件需要接入生产top，不能直接把所有记录位分配为板卡引脚。

后续把已经证实的CSI事件/完整身份形成记录、选择实际WIDTH和容量预算、连接帧写入/终态、证明接收closure，再完成板级CDC/引脚/PNR/STA。官方CSI ModelSim示例已在本机发现，尚未在本单元中执行。不把此FIFO组件或数量测试称作真实摄像头链路已经完成。
