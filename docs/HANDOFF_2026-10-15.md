# Ti60F225 V4 / SC431HAI：2026-10-15 实物调试交接

## 先看结论

更换故障摄像头模组后，用户确认官方 SC431HAI→HDMI v6/v7 能显示真实画面；v7 偏紫、v6 偏绿，颜色问题尚未定位。自研 031/refine 曾表现为 HDMI 无信号。获批的视频恢复 v1 已把输出修至可见彩条，但没有相机画面。随后获批的 DDR 阶段诊断 v1 在实物上的用户报告为：**D0 闪，D1–D5 亮，D6–D7 灭，屏幕仍是彩条**。按该版专用灯位映射，原始 `init_cur_state[6:0]=7'b0011111=0x1F`。

这只能说明诊断版的 `core_clk` 计数器在运行、DDR IP 的原始阶段输出在观察时为 `0x1F`、HDMI 彩条存在。`0x1F` 的厂商含义、`cal_done` 实际电平、阶段是否长期停滞、Programmer 日志均未独立确认。**不要把 D0 闪误判为 DDR 校准完成**：诊断版特意取消了 D0 的 `cal_done` 门控。两个版本的 D1–D7 含义也不同。

## 下一步建议

1. 先只读查 DDR IP 公开文档、受保护状态输出周边连线及 `cal_done` 生成/复位条件，确认 `0x1F` 能否可靠对应某个阶段。把“观察一次”与“持续稳定”分开。用户之前测到官方 demo 可出图，尽量在同一板、同一模组、同一连接条件下对照。
2. 若阶段语义仍不可得，设计并获批**最小诊断**：同时把 `cal_done`、相关锁定/复位和必要校准握手以可辨方式引出；有明确预期再构建与人工下载。不要仅凭 `0x1F` 盲改 `tFAW`、DDR 引脚或摄像头参数。
3. DDR 就绪后核对 `board_frame_system.sv` 的 `cal_ready → capture_start → frame publish → has_frame`，随后检查 CSI 帧/行/像素、RAW10 与 Bayer 相位。当前 PnR 仍有 `mipi_dp_data0_LP_P_IN/N_IN` 未布警告，须在实物画面恢复链路中核对其影响。
4. 有真实画面后才按灰度、中值、Sobel/Canny、叠加、识别逐项实测；复杂识别资源与准确率仍未闭合。偏紫/绿另对 Bayer 顺序、RAW10 解包及寄存器/白平衡作受控对照。
