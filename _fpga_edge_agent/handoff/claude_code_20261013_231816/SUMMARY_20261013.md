## 最新身份探测的确切含义

最后一次由Codex确认的下载：2026-10-13 22:24:59，Programmer日志出现 `Device is in user mode!` 和 `Programming operation completed.`；RST-COMPARE v1的bit SHA256为 `5F672543565226CD349ACDAE3DEB99420C7E8129DA8D8EE98859EB806A8C198C`，Programmer checksum为 `E34B8AD6`。若用户之后自行下载其他文件或断电，当前程序必须重新确认。

原ID和RST对照版灯义：D0为DDR校准完成条件下的主时钟计数心跳；D1为启动等待结束；D2/D4分别为7位0x30/0x32的首个写地址ACK；D3/D5为完整读取3107/3108且等于CD6B；D6为四笔尝试安全结束，普通NACK也算；D7为诊断定义的超时/仲裁/协议等故障。

最新用户明确反馈：**D0闪，D1亮，D2–D5灭，D6亮，D7灭**。按当前源码，四笔请求都在总线上首个地址字节0x60或0x64未取得ACK，然后STOP结束。后续寄存器地址、重复START和读数据没有走到。不能把这个结果写成“ID已读完但不匹配”。D7灭也不能证明SDA确实拉低、引脚/排线连通或传感器已经解除复位。

原RST低探测开始前等约20.2ms。高电平对照先保持RST低约20.2ms，再拉高，原probe再等待约20.2ms后探测；完成后约1.01ms恢复RST低并保存灯态。因此试验结束时RST低是预期，不证明试验中的RST高已到达芯片。

曾出现“全部常亮，D0/D1稍暗”，按SW0仍全亮。该观察留档，但不符合正常D6/D7互斥终态，不能当作相机全部应答。GUI重新下载后已取得上述可解释灯态；早先全亮原因未定。
