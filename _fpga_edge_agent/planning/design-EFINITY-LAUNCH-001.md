## 整体行为、职责与接口

| REQ | 要求 | MOD / IF | 验证 |
|---|---|---|---|
| R1 | R: 已占用时仍可通过固定路径启动；不改已有映射 | M1 路径检查 → I1 程序/工作目录 | T1/T3 |
| R2 | 工具和用户配置均使用一致的ASCII路径；全局环境不变 | M2 环境及局部配置 → I2 子进程环境 | T2/T3 |
| R3 | 启动失败保留可读原因；成功须有响应中的Efinity主窗口证据 | M3 启动与退出 → I3 窗口/退出码 | T3/T4 |
| R4 | 旧文件可回退、源和其他任务不受影响 | M1–M3、备份/差异 | T1/T5 |

连接：用户双击 → M1检查现有工具/工作目录 → M2调用现有setup并指定项目局部配置 → M3启动Efinity → 用户查看GUI/退出。任何前置失败返回错误，不尝试重映射盘符或改装工具。正常样例是当前R盘占用但固定路径有效，GUI应仍可打开；失败样例是工具别名目标不存在，显示具体缺失路径且不启动、不修改R盘。

I1：本机只读路径字符串。工具根为 `C:\Users\34528\FPGAEdgeLinks\Efinity2026_1`；工作根为 `C:\Users\34528\FPGAEdgeLinks\Work\active\gui_led`。两者实际目标已核对；保留引号，cmd文件保持ASCII无BOM并使用Windows换行。

I2：setup.bat 在当前 setlocal 作用域设置 Efinity/Python/Qt变量；它会覆盖 EFINITY_USER_DIR_INI，因此在调用之后指定局部 user_dir.ini 和 efinity_user 路径。路径值指向同一Work目录；INI只替换本任务明确的旧前缀，保留其它字段、章节和偏好。PYTHONDONTWRITEBYTECODE继续生效。环境随启动器退出而释放，子进程在创建时继承，不写注册表或setx。

I3：M3在指定工作目录启动现有 efinity.exe，并等待该实例结束；传递真实退出码。GUI通常一直运行到用户关闭，等待本身不视为失败。缺路径、不能进入工作目录或启动返回失败时留可见提示；成功也不能只以返回码或已有进程冒称出现新窗口。无网络、硬件或数据库接口。

组合检查：仅换程序路径仍会遗留R工作目录/INI，故三个路径来源必须一致。现有R映射归属不明，对本方案无依赖；全程不创建/删除它。open_last_project保持off，试开不自动接续历史工程操作。

## 局部中文草图、状态和不变量

1. 获批后复核基线；若用户已改脚本或INI，先检查差异，不整份覆盖。复制4个拟改文件到审计目录作本次备份，再按上述范围修改。
2. 启动器进入局部环境作用域，确定固定工具与工作目录；核查exe、setup、工作目录和局部配置存在。缺任何必需项则显示对应路径、暂停让用户读错并返回非零；不安装、不重建别名、不覆盖用户配置。
3. 调用原厂setup；再指定局部INI/用户目录与禁止pycache选项。核对关键环境目录存在，再进入工作目录；进入失败时走错误路径，不能退回中文当前目录继续启动。
4. 显示可打开的英文工程路径，启动GUI并等待；退出后先保存返回码，再恢复工作目录和结束局部环境，返回所保存的代码。非零退出留可见提示，不自行重复启动。
5. 用户提前关闭启动器也不执行盘符清理；后续Efinity子工具仍可使用持久别名。正在运行中的Efinity不强杀；修改/恢复INI前先确认相关实例已退出，避免覆盖它的配置写入。

局部状态是前置检查、环境就绪、GUI运行、结束/失败；由启动器进程拥有。返回码先保存再进行清理，避免popd等操作覆盖。全程保持“既有映射不变”“配置值指向同一工作包”“不执行编译/下载”三个不变量。无队列、数值算法、C++/RTL或跨语言映射；相应硬件时序/位宽约束不适用。cmd关键条件是参数引用、编码、环境继承、错误码及GUI进程生命周期。
