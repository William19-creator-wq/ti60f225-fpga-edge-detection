## 找到的代码问题

Efinix 官方 [MIPI CSI-2 RX Controller User Guide，表 19，第 14 页](https://www.efinixinc.com/docs/mipi-csi2-rx-core-ug-v3.2.pdf#page=14) 规定 RAW10 四像素由低位向高位排列：首像素 `[9:0]`，然后 `[19:10]`、`[29:20]`、`[39:30]`。工程启用 Pack_40；以下以 P0–P3 表示这四个像素的高 8 位。

| 环节 | 原连接 | 修正连接 |
|---|---|---|
| 输入 32 位字，从高位到低位 | P3、P2、P1、P0 | P1、P0、P3、P2 |
| 32→128 打包 | 早到的 32 位字位于高位 | 相同 |
| 128→16 拆包 | 高 16 位先输出 | 相同 |
| 下游每拍两个像素 | 低字节为先像素 | 相同 |
| 实际输出空间顺序 | **P2、P3、P0、P1** | **P0、P1、P2、P3** |

错序在每四像素中将两对像素交换，保留了像素数量、行长度及 Bayer 奇偶关系。因此它可以与“计数为 1920×1080、颜色大体正确”同时存在，并可能使细节错位。其对当前实机颗粒感的贡献需下载对照；单凭计数不能排除这类内容错误。

实际例化链已核查：frame_buffer → vid_rx_align_v1 / ser2par_v1 → ddr_buffer / **ddr_wr_buffer1（文件 ddr_wr_buffer.v）** / ddr_rd_buffer → vid_par2ser → cvo_axi_v1。写读数据均保留整个 128 位字，未发现额外字节重排。详细行号与哈希见 [data-path-evidence.json](D:/大三/FPGA_verilog/_fpga_edge_agent/reports/TRACK4-V7-PIXEL-ORDER-001/data-path-evidence.json)。没有将未使用的另一套 par2ser 或同名近似模块当作实际路径。

还对照了本机资料包的原始 v7：上述顶层输入拼接相同，相关四份打包/拆包和 DDR 读写 RTL 与当前副本逐字节一致，且原文件哈希符合此前重建时的输入登记。它是 v7 派生链继承的连接，不是本次细线图新增的行为。原始资料保持只读，证据见 [official-v7-origin.json](D:/大三/FPGA_verilog/_fpga_edge_agent/reports/TRACK4-V7-PIXEL-ORDER-001/official-v7-origin.json)。此处核对针对像素顺序，不代表原 031/refine 无信号原因已经闭环。
